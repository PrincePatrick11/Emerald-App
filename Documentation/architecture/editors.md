# Editors

Editors that more than one place embeds live in `src/components/editors/`, one folder each, with an `index.ts` as the public entry. A place that embeds one imports from that index, not from the files inside. Each editor is neutral: it knows its document, its features and its chrome, not the place that embeds it; what belongs to a place (storage, migration, settings of its own) sits in that place as a thin adapter.

## Shared Parts

`src/components/editors/shared/` holds the chrome every editor's bar uses: `toolbarParts.tsx` (`ToolbarBtn`, `ToolbarGroup`, `ToolbarDivider`; 28px buttons, neutral on hover and jade when active, `--editor-toolbar-active-*`) and `PopoverButton` (a bar button with a small panel under it, `.editor-toolbar-popover`, closed by a click elsewhere or Escape through `useOutsideClick`, opening towards the left from the bar's right half). Pointer drags inside an editor (resizing, moving, marking) go through `trackPointerDrag` in `src/lib/pointerDrag.ts`.

## Text Editor

`src/components/editors/text/` is the rich-text editor: TipTap (ProseMirror), saving HTML. Entries use it for their text blocks and for the text elements of user-built blocks; `TasksView` uses its `LinkPickerModal`.

### Parts

- **`TextEditor`** — one writing surface. *Props:* `initialContent` (initial value only; remount via `key` to load other content), `onChange(html)`, `editable`, `placeholder`, `features`, `hostKey`. It also holds what belongs to exactly this editor: the extensions, the chip lookups, the popup for external links, pasting images.
- **`useTextEditorHost`** — what may exist only once for a set of editors shown together: the one toolbar, bound to the focused editor; the find bar; the word count while editing (`WordCount`: words and characters of all editors, a link chip counted with its label, recounted at most once per frame); `LinkPickerModal`; chip-click navigation in read mode; OS file drops; pointer drops from the entry list; `DragGhost`. It returns `context` for `TextEditorHostContext`, the `toolbar`, `wordCount` and `overlays` to render, `dropActive` for highlighting, and `orderedEditors`/`targetEditor`/`focusOnMount` for requests the host handles itself.
- **`useTextEditorRegistry`** — the host's bookkeeping: which editors exist under which key, in what order (`getOrder`), which was focused last. The focused editor, else the last one, gets the toolbar and receives requests from outside.
- **`SelectionMenus`** — the small menus at a selection, rendered by each `TextEditor` through TipTap's `BubbleMenu` while it is editable (each menu is a plugin that follows every transaction): over selected text the marks, a text colour and a web link (both chosen in the menu itself), over a selected image alignment, three widths and removing; at the top edge of a table the cursor is in its rows, columns, header row and removing. The image and table menus are anchored to the picture and the table, not to the node's full-width element; a cell selection shows only the table menu. Like the toolbar they show what the schema has, and they subscribe to the editor state with `useEditorState`, since the editor does not re-render per transaction.
- **`slashCommands.ts`** — the `/` menu (`CommandList`): typed at the start of a line or after a space, it lists what the editor's schema has (text, headings, lists, checklist, quote, rule, collapsible section, table, image, entry link) and filters by the translated label and English keywords. The entry link types `[[`, which opens the link suggestion in place; the image opens a file picker for several files.
- **`suggestionPopup.ts`** — the popup both suggestions (`[[`, `/`) render in. The suggestion plugin mounts and places it at the caret (`props.mount`, Floating UI) and closes it on Escape and on a click outside.
- **`EditorToolbar`** — the formatting bar: a rounded surface (`.editor-toolbar`, panel colours with an edge) in the sticky strip, which has the sheet's colour. Its buttons come from the [shared parts](#shared-parts), as do those of the selection menus, the link popup and the find bar. Marks and alignment come from one table, `formatActions.ts`, which toolbar and selection menu both render. Its groups follow the order of writing: undo and redo, headings, marks with the text colour, alignment, lists with checklist, quote and collapsible section (`toggleDetails`: wraps the selected blocks, or unwraps the section the cursor is in, leaving no empty summary behind), then what is put in (entry link, web link, image, table, divider), and the magnifier for the find bar at the far end. Web link and text colour are `PopoverButton`s: the web link's `LinkHrefForm` sets the address of the selection or of the link at the cursor, offers removing that link, and with nothing selected puts the address in as new linked text; the colour panel is the selection menu's `TextColorSwatches`, for the selection or for what is typed next.
- **`LinkHrefForm`** — the web address of a link typed in place, in the selection menu (a new link), the toolbar and the link popup (a changed one), with the `.editor-inline-input` field. `applyLinkHref` sets the address, inserts it as linked text when nothing is selected, or takes the link away when it is empty.
- **`features.ts`** — `TextFeatures`, the switches an embedding place sets, and `FULL_TEXT_FEATURES`.
- **`editorCommands.ts`** — commands on an editor: appending, finding, revealing and removing a link chip; `revealPosition` (unfolds headings and opens collapsible sections around a position, for the find bar and "show link" from the sidebar); `insertImageFiles` for pasted files (other formats left out with the format notice) and `pickImageFiles` for the picture picker (`pickPictures` in `store/imagePickerStore.ts`, shown by `ImagePickerHost` in the shell: "Images" or the disk; the text's own file drop stands aside while it is open); `insertImagesInOrder`, which they and file drops share: several images one behind the other from the cursor or the drop spot, the spot following every change while a photo is prepared, one failure not stopping the rest; `NEW_TABLE`.
- **`useEditorsUpdate`** — follows the content changes of a set of editors, optionally at most once per frame; the find bar and the word count use it.
- **`useListKeys`** (`suggestionPopup.ts`) — arrow keys, Enter and Tab of both suggestion lists; an empty list leaves the keys to the editor.

### Embedding

A single `TextEditor` works on its own, without a toolbar (Markdown shortcuts and paste still apply). For a toolbar, or several editors in one document, the place calls `useTextEditorHost`, wraps its content in `TextEditorHostContext.Provider value={host.context}`, renders `host.toolbar` and `host.overlays`, and gives each `TextEditor` a `hostKey` that `getOrder` lists in document order. `BlockStack` does exactly that: the keys are block IDs, and `<block ID>:<element ID>` for a user-built block's text element.

Requests that depend on the place's content stay with the place. `BlockStack` handles the sidebar's link requests itself, because they also reach link fields, and uses `orderedEditors`/`targetEditor` to find the editor.

### Features

`TextFeatures` switches parts of the editor on or off: `structure` (headings, quote, horizontal rule), `folding` (by headings, needs `structure`), `lists`, `tasks`, `highlight`, `colors`, `align`, `links` (external), `entryLinks` (chips, `[[`, link picker, drops from the entry list) `images` (paste, file drops, image button), `tables`, `details` (collapsible sections) and `commands` (the `/` menu). The default is everything, which is what entries use.

A switched-off feature is missing from the schema, not only from the toolbar. Content that uses it is dropped when the editor loads it, and the next change saves the content without it, so features are switched off only where such content cannot exist yet. The toolbar asks the editor's schema (`editorHas`), not the feature set, so it always matches what the editor can do. The host also sends file drops only to an editor with images and pointer drops only to editors with link chips.

`features` is read once, when the editor is created, like the formatting settings under Settings → Entries ([Vault Settings](storage.md#vault-settings)).

### Images and drops

Every drag into the host's editors goes through one geometry (`dropSpot.ts`): `editorAtPoint` finds the editor under the pointer, or the nearest one when the pointer is between them; `lineSpot` gives the position between two top-level blocks, `caretSpot` the one between two characters. `DropIndicator` draws a line or a caret there while the drag runs. It listens to its own channel, so a pointer move does not re-render the host.

- **Files from the explorer** (`useEditorFileDrop`) land between the blocks under the pointer, several in the order of the files. Tauri calls the event's position physical, but only WebView2 delivers device pixels (divided by `devicePixelRatio`, which includes the page zoom there); WKWebView and WebKitGTK deliver the view's points, unzoomed, so there the UI scale divides (wry, `wkwebview/drag_drop.rs` and `webkitgtk/drag_drop.rs`). Dropped beside all editors, they go to the cursor of the focused editor. While the files are prepared the spot follows every change of the document, so typing meanwhile does not split a paragraph. A file is read in and prepared when that could change it (`needsPreparing`), else copied as it is; one too large to read in is copied too while the vault sets no limits.
- **Entries from the list** (`useEditorPointerDrops`) become a link chip at the caret.
- **Images in the text** are moved by dragging them once selected, as in a word processor. Not yet selected, a press on one is the node view's own: a click selects it, and a drag marks text from the image's far edge to the pointer, since the page starts no selection from a node that is not editable. Marking across images, from the text or from an image, takes the image under the pointer in at once (`imageSelection.ts`): the page's own drag selection does not move over a node that is not editable, so a plugin follows the pointer and puts the head past that image. While a selection covers images they are tinted, and the editor draws the selected text itself, since a selection ending between two images is one the page cannot show. Its colour is the app's selection colour (the theme token `--selection-bg`), which the page's own selection uses too, so the two never differ. The WebView has no HTML5 drag, so the image node is not `draggable` for ProseMirror; for a selected image the node view starts a pointer drag after a few pixels (`imageDrag.ts`), and the host's listener moves it at `pointerup`. Within one editor that is one transaction and one undo step; into another editor of the host it is inserted there and then removed at the source. The moved image ends up selected. A cancelled pointer (touch panning, a native drag) ends the drag without moving; while editing the image has `touch-action: none`.
- **Paste, the image button and the `/` menu** take several images at once, in their order (`insertImageFiles`).

The drop line skips blocks that are folded away, which have no box.

### Find and replace

⌘F on macOS, Ctrl+F elsewhere (on macOS Ctrl+F is the system's "one character forward") opens `FindBar` in the host that is on screen (its container has a layout box), in reading and in editing; a selected text is searched for first. It sits with the toolbar in the one sticky strip, a surface of the same shape: the field with its count inside, the arrows, the switch for replacing and closing, and when replacing a second row with its own field and the buttons Replace and Replace all. The toolbar's magnifier opens and closes it too. `SearchExtension` marks the hits in every editor as decorations and finds them again after every change; the bar hands each editor the query and, for the one holding it, where the current hit starts (`setSearch`, kept out of the undo history, mapped through later changes). Case is folded one character at a time, keeping the length, so positions in the text stay positions in the document — a character whose lower case is longer, such as "İ", is compared as it is. A hit runs across marks but not across paragraphs, and an inline node such as a link chip matches nothing. The current hit is made visible (`revealPosition`): its heading unfolds and its collapsible section opens, and the focus returns to the field. Enter goes to the next hit, Shift+Enter to the previous, Escape closes and takes the marks away. While editing the bar also replaces: the current hit — after which the next hit is the first behind the new text, so a replacement that still matches is not hit again — or all of them, from the back and in one undo step per editor.

### Folding by headings

`HeadingFoldExtension` gives every top-level heading with something under it a chevron in the left margin, shown on hover and while folded: in the page margin while reading, in the frame's inner padding while editing, at a fixed size so it does not grow into the text of an H1. Folding hides everything after the heading up to the next heading of the same or a higher level, so an H1 takes its H2s and H3s along; a folded heading ends in `…`. It is decorations only and is not stored, so it works while reading, survives the switch to editing and every heading opens unfolded. Folded positions are mapped through every change. A selection that lands in a folded section unfolds it, and so do a find-bar hit and "show link" from the sidebar (`revealPosition`). The sections are worked out once per change. Folding works within one text block, not across the blocks of an entry.

### Collapsible sections

`@tiptap/extension-details`: a heading line (`summary`) with a toggle beside it and the content under it, inserted from the `/` menu. The open state is not stored (`persist: false`): opening a section while reading would otherwise change the content. Every section therefore opens closed. The toggle's label is translated; an empty heading line shows its own placeholder, for which `Placeholder` runs with `includeChildren` (the stylesheet still shows the editor's own placeholder only in an empty editor). The PDF export opens every section, or its content would be missing on paper; the Markdown export writes the heading line in bold and the content after it.

### Text colours

`TextColorMark` stores a colour by name only: `<span data-color="blue">`, one of six (`TEXT_COLORS` in `lib/textColors.ts`, which also holds the shades), anything else is not parsed. The shade comes from the theme (`--editor-color-<name>`, light shades in Noctis, dark ones in Parchment, see [themes.md](../themes.md)), so text coloured in one theme stays readable in the other. The PDF export prints the light shades, built from the same list; Markdown has no colour and keeps the text. Import and PDF export let `data-color` through.

### Tables

`TableKit` from `@tiptap/extension-table`, with resizable columns. A table looks like the app's other surfaces: a rounded frame with an edge, quiet inner lines and the header row on the panel colour; it uses `border-collapse: separate`, since collapsed borders cannot round their outer corners. A new table has three rows and three columns, the first a header row (`NEW_TABLE`, shared by toolbar and `/` menu). Column widths are stored as `colwidth` on the cells and again as `<col style>` widths, which the import and the PDF export's sanitiser let through; the PDF holds every table to the text column, since a resized table carries a pixel width that could be wider than the page. The Markdown export (`createMarkdownConverter` in `lib/export.ts`) writes a GFM pipe table: the first row is the header, as GFM requires one, a cell's paragraphs are joined with `<br>` and pipes escaped. Markdown import reads GFM tables through `marked`.

### Image sizes

An image is decoded asynchronously and loaded lazily (`decoding`, `loading` on the `img`): it is stored at the size it came in unless the vault has [image limits](storage.md#vault-settings), and a phone photo decoded at full size on the main thread would stall typing and scrolling.

Resizing drags a handle on the side that moves: right for a left-aligned image, left for a right-aligned one, both for a centred one, where the width changes twice as fast as the pointer. The width is stored in pixels, so an image keeps its size when the window changes; `max-width: 100%` only shrinks it where the text column gets narrower. While dragging it snaps to 25, 33, 50, 66 and 75 % of the editor's current width within two points, and shows in the image's corner. Dragged to the full width, and the menu's 100 %, store `100%`, which is meant to follow the text; the menu's 25 and 50 % store the pixels of that moment. A percentage below 100 from before is converted to the pixels of the moment when the editor starts editing (`pinPercentImageWidths`), outside the undo history and without an update event: merely opening an entry for editing does not count as a change, and the new widths are saved with the first real one.

## Canvas Editor

`src/components/editors/canvas/` is one editor for pictures and painting: elements on an artboard (pictures, shapes, text, drawings, and any kind a place registers), moved, scaled and rotated with handles, and painted in, inside a drawing element, with the paint tools. It draws with Konva through `react-konva`; strokes are vector paths from `perfect-freehand`. It is neutral: it knows a scene of elements and a registry of element types, not the place. A profile says what a place offers (see [Profiles](#profiles)); the Canvas and Altar blocks offer everything, less the parts a block switched off ([Canvas blocks](#canvas-blocks)), a sigil drawing only the paint tools on one drawing ([Sigil drawings](#sigil-drawings)), and other places, Servitors for one, can do the same with their own adapter.

The shell is the folder's top level (stage, elements, toolbar, history, zoom); painting is `paint/` inside it (the paint mode's surface, bar and layer panel, the drawing type, rendering), on top of the pure document in `src/lib/paint/document.ts`. The public entry is the folder's `index.ts`.

### Parts

- **`CanvasEditor`** — the stage. *Props:* `width`/`height` (the artboard in its own pixels), `elements` and `onChange(elements)` (the place owns the scene; every change arrives as the whole new list), `selectedIds` and `onSelectionChange`, `editable`, `types` (the registry, default `BUILTIN_CANVAS_TYPES`), `features`, `background` (DOM painted behind the artboard, such as a CSS gradient or image), `canvasBackground`, `onCanvasBackgroundChange` and `backgroundImages` (the artboard's own background, drawn behind the elements and saved with the exports, with the bar's panel to change it; it takes the place of `background`), `grid`, `rotationSnap`, `historyKey` (undo starts over when it changes), `readAlign` (the artboard at the top or in the middle while reading), `createId`, `onEditElement` (double-click or Enter on an element whose type has no typing in place, for opening it in an editor of its own), `onExport(options)` (the toolbar's save button opens `ExportDialog`, the place saves what it asks for), `overlay` (drawn over the viewport), `toolbarEnd`, `elementLabel` (the place's name for an element in the element list, such as a library item's name), and `guides`, `onGuidesChange`, `guidesLocked` and `onGuidesLockedChange` for the ruler guides. `paint` (palette, brush to start with and `PaintFeatures` of the paint mode), `paintElementId` (fixes the editor in the paint mode of that element: it starts there and stays, with nothing else to select or add) and `layout` (`fill` its positioned parent, or `inline` in the flow, the stage in the artboard's shape). Its handle (`ref`) gives `clientToArtboard`, for drops from outside, and `visibleCentre`.
- **`CanvasToolbar`** — the bar while editing, built from the [shared parts](#shared-parts), so the editors look alike. Like the paint mode's bar it keeps its place, and adding is not in it: undo and redo; the `controls` of each type in the selection (fill, outline and the corners of a polygon or points of a star for shapes, font, size, bold, italic, alignment and colour for text); Align (edges and centres of the selection, or of the artboard for one element; even gaps from three; a group aligns as one, its members keeping their places to each other); at the far end the element list and saving as an image. Stacking, grouping, duplicating and removing are in the element list, as the paint mode's layer operations are in its layer panel; a place without the list (`layers` off) gets Arrange (to front, forward, backward, to back), grouping, duplicating and removing in the bar instead. A value the selection does not share shows empty. Zoom out, the zoom level (a click fits the view) and zoom in sit in a small bar of their own in the stage's lower right corner (`CanvasZoom`), so the bar stays one row beside a sidebar.
- **`CanvasToolRail`** (in `CanvasToolbar.tsx`) — the tools in a column over the stage's left edge, laid out like the paint mode's `PaintToolRail`: selecting (V), then each registered type's `additions` as a group (rectangle R, ellipse O, polygon G, star S, symbol Y, text T, drawing P; the letters from `CanvasAddition.shortcut`, the paint mode's for the same shapes). A picked tool draws its element on the stage: dragging gives the box (Shift a square; a type that keeps its proportions takes the width, text the width and the height it needs), while the pointer is down the element itself is drawn in it with a dashed frame, never committed until the pointer lets go; a click puts it there at the addition's own size; the stage shows a crosshair while a tool is picked. Then the column goes back to selecting, a new text is typed into and a new drawing painted in. Escape drops the tool. While editing, the artboard fits beside the column.
- **`TextEditOverlay`** — typing into an element whose type has `textEdit`: a text field laid exactly over it, in the type's look (`textEdit.style`), scaled with the view and turned with the element, while the element is hidden. A click elsewhere, Escape or ⌘/Ctrl+Enter end it and keep the text; a text left empty is removed. A new element of such a type starts in it with its placeholder selected. A new element lands in the middle of the visible artboard, a step down and to the right while something already sits there.
- **`elements/`** — the built-in types, `BUILTIN_CANVAS_TYPES`: `image` (a picture contained in its box, or its emoji while the picture loads or when it has none, at 80 % of the box; `glow` adds a warm flickering light), `shape` (rectangle, ellipse, polygon and star with 3–12 corners or points, drawn like the paint mode's (`polygonPoints`); fill, outline, outline width, rounded corners for rectangles; the triangle and hexagon of older altars still draw, and changing their corners makes them polygons) and `text` (wrapped at the box's width, words first, characters for a word wider than the box, in one of three bundled fonts: Cormorant Garamond, Lora, Inter). `controlParts.tsx` holds what their controls share: `ColorPanel` (twelve swatches, "none" where it makes sense, the system's picker), `NumberField`, `common`.
- **`draw.ts`** — `drawElement` and `drawPlaced` through the registry, shared by the stage and the export; an element of an unregistered type is a dashed box, so it stays visible and can be moved or removed. `resourcesOf` collects the picture sources and fonts the elements need.
- **`symbols/`** — the symbol library and the `symbol` element type (one of the built-in types). `packs.ts` holds `SYMBOL_PACKS`, each symbol an id `pack.name`, centre-line path data in a box of 100 × 100 and, for dots and discs, `solid` path data filled in the line colour, and for dense ones a starting `weight`, built with `paths.ts` (`circle`, `line`, `poly`, `starPolygon`); its name is the translation `symbols.<pack>.<name>`. `symbolType.tsx` draws the path as round-capped lines of `weight` in `color` (a `Path2D` per path, cached), its closed parts filled with `fill`, and writes the same as an SVG path; the element keeps its path data, so it draws without its pack. Its controls swap the symbol, set line colour, fill and weight. Its addition has a `picker` (`SymbolPicker.tsx`: search, packs, grid), which `CanvasToolRail` opens beside the column; picking chooses the tool. `limits.ts` holds the weight's range and `isSymbolPath`, free of React for the storage code (`lib/userSymbols.ts`, and `lib/altarElements.ts` for converting older altars). A place passes `symbolLibrary` (`library.ts`: its own symbols as `own.<id>` with a `name`, `save`, `remove`), which the editor hands down through `SymbolLibraryContext`: the picker shows them as the pack `own` with a remove button each, and a selected drawing gets `SaveAsSymbol` in the bar, which turns it into a symbol with `symbolFromDrawing` (`fromDrawing.ts`: the visible strokes fitted into the box through `buildStrokePath` with a mapping `PathSink`, pen strokes, fills and filled shapes as `solid`, lines and outlined shapes as `d` of their mean width, erasers and layer pictures left out). The blocks' library comes from `symbolStore` (table `symbols`).
- **`background.ts`** — `CanvasBackground`, the artboard's background as a setting of the canvas: a `fill` (none, a colour, a linear gradient at a CSS angle, or a radial one from a centre to the farthest corner, with two or three colours), an `image` (the place's reference, covering or contained) and a `tint`. `backgroundCss` shows it on the stage, `drawCanvasBackground` and `backgroundSvg` draw it for the exports (gradients stay gradients in SVG), `parseCanvasBackground` checks a stored one.
- **`BackgroundPanel.tsx`** — the bar's background button and panel, offered when the place passes `onCanvasBackgroundChange`: the fill's kind, its colour or the gradient's colours (one picked at a time, a third added or one removed), the angle or the radial centre, choosing and removing the picture (`backgroundImages.pick`, the place stores it) and its fit, and the tint with its strength. Every change goes to the place at once.
- **`svg.ts`** — `SvgPath`, which takes the canvas path calls (`PathSink`, met by `Path2D` too) and gives path data, so the shape and paint path code draws on a canvas and writes SVG alike; `attrs` and `esc` for writing elements.
- **`ExportDialog.tsx`** — the dialog behind the bar's save button: format (PNG, JPEG, SVG), the whole artboard or the selection's box, a factor (½, 1, 2, 4, up to 16384 pixels a side) or a typed width or height, and the background when the place has one (always for JPEG). The choices hold for the next export while the window is open. It hands `CanvasExportOptions` to the place's `onExport`, which renders and saves; no place passes one at present, and without it the bar has no save button.
- **`exportImage.ts`** — `renderCanvasImage` draws an artboard onto a fresh canvas without the editor, after a `drawBackground` callback, with fonts and pictures loaded first (`loadImage`; for a canvas read back with `toBlob`, the place hands in elements whose sources are data URLs); `canvasToDataUrl` reads it out. Both take a `region` (a part of the artboard) and an `outWidth`. Both draw a `background` (`CanvasBackground`) first. `renderCanvasSvg` writes the same as an SVG document: each element a group with its frame, rotation and opacity, its content from the type's `svg` (shapes as paths, text as text in its fonts, named, a picture embedded with its glow as a filter, a drawing as its strokes with erasers as masks) or, for a type without one, its drawn picture embedded; the background embedded as a picture behind them.
- **`useCanvasHistory`** — undo and redo, see [History](#history).
- **`canvasActions.ts`** — list changes shared by toolbar, keys and the element list: `arrange`, `align`, `distribute`, `copiesOf` (copied groups become new groups), `nudge`, `group` (the selection with its groups, stacked together where its topmost member was), `ungroup`, `withGroups` (ids with the rest of their groups), `moveInStack`. Locked elements stay where they are.
- **`ElementList.tsx`** — the elements as a list over the stage's right side, top first, each with a small picture and the type's `label` (or the place's `elementLabel`), an eye and a lock. A click selects (Shift or ⌘ adds), dragging a row restacks; members of a group that lie together get a head row that selects, hides or locks them all and drags them together. Clicking a member in the list picks it alone. Below the rows: the opacity of the selection, then duplicating, grouping, ungrouping and removing it.
- **`Rulers.tsx`** — the rulers right at the artboard's top and left edge, as long as it is and kept in view when it runs past the stage (`rulerLayout`), in artboard pixels (labelled every 1, 2 or 5 times a power of ten, at least 56 screen pixels apart, with half and tenth steps between when there is room), the selection's span tinted in the accent and each guide's place notched on the stage's side, switched on in the bar's end (with `guides` on; the choice holds for every canvas editor in the window). Pressing a ruler and dragging onto the stage pulls out a guide, from the top a horizontal one, from the left a vertical one; a guide is dragged to move it and dropped on a ruler to remove it. Guides are snapped to like the other elements' edges while moving, and a dragged handle snaps to them and to the artboard's edges and middle, in the transformer's `boundBoxFunc` (`snapBoxEdges`: the moving edges of an unrotated box; a box keeping its proportions takes the edge that snapped and fits the other side). A place that keeps them passes `guides` and `onGuidesChange` (the whole list once a drag ends) and `guidesLocked` with `onGuidesLockedChange`; otherwise the editor keeps them per `historyKey` while the window is open. While the rulers show, the bar has a lock: locked guides take no presses, so they can be neither moved nor removed, and the elements under them stay reachable. 
- **`CanvasContextMenu.tsx`** — the entries of the right-click menu on the stage (`canvasMenuActions`), with the keys as `shortcuts.ts` writes them for the platform, shown with the app's `ContextMenu`. A right click on an element selects it with its group unless it is selected already, then offers cut, copy, paste, duplicate, the four stacking moves, group and ungroup, lock, hide and remove, each with its key; on the empty stage paste (the copies' middle where the menu opened), select all, fit and the rulers; on a locked element, found by its box since it takes no presses, only unlocking it. Entries that do not fit are greyed out rather than left out. Not in the paint mode, and only while editing.
- **`ShortcutOverview.tsx`** — a `Modal` with every key and gesture of the editor, opened with `?` or the keyboard button at the bar's end, in both bars: in the paint mode the drawing's tools, brush and selection keys, otherwise the tool column's letters, selecting, editing, the modifiers while dragging (Shift draws squares and keeps proportions while scaling, Alt scales from the centre and moves without snapping) and the view; each only where its feature is on. While it is open the editor takes no keys, so Escape closes it.
- **`LayerDock.tsx`** — the frame the element list and the paint mode's `LayerPanel` share, so both look and work alike: the panel with its head, rows with a 48×32 picture, lock and eye (`DockToggles`), and a footer with an opacity (`DockOpacity`) and a row of buttons.
- **`snapping.ts`**, **`geometry.ts`** — guides and grid steps; the box around a rotated element, unions and intersections.
- **Emoji** are drawn with an opaque fill: WebKit draws a colour emoji with the alpha of the current `fillStyle`, which in an export may still be the background's overlay.
- **`imageCache.ts`** — the pictures elements draw from, loaded once per source for every canvas editor; `useCanvasResources` also loads the fonts and redraws when something arrives.
- **`paint/drawing.tsx`** — `createDrawingType`, the element type of a drawing, made by the place that registers it, since it knows where layer images live (`resolveImage`). It holds a paint document and draws it into its box through `drawPaintDoc`, cached per document and pixel size, since the stage redraws a whole layer for every move. Its `paint` entry makes it paintable; adding one from the toolbar makes a 3:2 drawing and enters the paint mode.
- **`paint/PaintSurface.tsx`** — the drawing surface of the paint mode, laid over the drawing being painted: its box on screen, turned with it, the canvas at that box's pixels. Every layer has a canvas of its own: a new stroke is added to its layer's canvas alone, anything else redraws that layer, and the visible canvas stacks the layers. The stroke being drawn lives in a ref and is drawn once per frame on a copy of its layer, so an eraser stroke cuts only its own layer and a long stroke re-renders nothing. Layers are stacked with their opacity. Pointer events with pen pressure and coalesced events; once a pen has been used, touches are ignored; Shift makes lines step by 15° and shapes even; Escape drops what a gesture was doing. The brush's outline follows the pointer. Besides drawing it selects strokes of the layer drawn on: a click takes the stroke under the pointer (hit-tested on its path, Shift adds or removes), a rectangle or a lasso takes every stroke lying wholly inside (`strokeSamples`, `inPolygon`) and cuts a freehand stroke that reaches out of it where it leaves (`splitStroke`: runs of points inside and outside, each reaching one point into its neighbour so the pieces meet), taking the pieces inside; the cut is a step of its own, lines, shapes and fills are only taken whole, and the selection gets a frame (an SVG over the canvas) whose inside moves, whose corners scale around the opposite corner and whose knob turns around the centre (Shift: one axis, 15° steps). The move tool shifts the whole layer, image included. While a gesture runs, its layer is drawn with the transform applied each frame; on release the transform is baked into the strokes (`transformStroke`) as one step. The picker reads the colour from the visible canvas; Alt with the pen or the bucket picks too, while with a shape Alt draws it from the middle out. The bucket fills the area around a spot (`paint/fillArea.ts`): the visible layers are drawn at the document's size, the pixels alike to the spot flooded, the area grown by a pixel to tuck under the lines' soft edges, traced along the pixel edges into closed rings (holes among them), and straightened with Douglas–Peucker; the result is a `fill` stroke. With the grid's snapping on, a shape's corners (or a line's ends) land on its crossings, unless Shift constrains them, and selections and layers move by whole cells. In symmetry the stroke being drawn shows with its copies, and the axes or rays show as dashed guides while a drawing tool is picked. A locked layer takes nothing but the picker. Under the pointer a ring shows the brush's size for the pen and the eraser; lines, shapes and the picker take a crosshair.
- **`paint/PaintToolbar.tsx`**, **`paint/LayerPanel.tsx`** — the paint mode's controls, built from the shared parts. `PaintToolRail` is a column of the tools laid over the drawing's left edge: those that work on what is drawn (select, lasso, move layer), those that draw (pen, line, ellipse, rectangle, polygon, star), then the bucket, the eraser and the picker. `PaintToolbar` takes the editor's bar, and what is always there keeps its place: undo and redo (the editor's one history), the brush's colours (the place's palette and, with `customColor`, the system's picker) and its size (a slider with a dot of the brush), both right in the bar, symmetry (off, mirrored, four quarters, radial with 3–16 rays), the grid (shown or not, snapping or not, 4–48 square cells across; the page's middle lines stand out) and the layer panel's switch; only after them what the picked tool alone has (filled or outlined, the corners of a polygon or points of a star), so showing it moves nothing; clearing and leaving the paint mode are at the far end. `LayerPanel` (on `LayerDock`) lies over the drawing's right side and stays open while painting, the editor keeping it open or closed between drawings. The top layer comes first, each row with a picture of the layer, its name (and opacity when not full), lock and eye: a click picks the layer drawn on, a drag moves it to another place (Alt with the arrow keys too), a double click on the name renames. Below the list, for the layer drawn on: its opacity, then adding a layer above it, copying it, merging it into the one below (not when it holds an image or eraser strokes, which would change the look) and removing it (the last layer is emptied instead). A layer holding an image shows the image mark. The floating parts are solid, like the menus, since the drawing runs under them.
- **`paint/usePaintTools.ts`** — `usePaintBrush` (tool, colour, size, the layer drawn on; they outlive the drawing painted) and `usePaintControls`, which turns a drawing's document, the brush and the editor's commit into what bar, panel and surface call (`PaintControls`).
- **`paint/render.ts`** — a pen or eraser stroke is `perfect-freehand`'s outline as a `Path2D`, its width following the pen's pressure or, without one, the speed; the eraser has an even width and cuts with `destination-out`. Shapes are stroked paths of the brush's width. Paths are cached per stroke. `drawPaintDoc` draws a document onto any canvas, filling its width or, given a box, scaled into that box at the origin of the target's current transform, stacking the layers on a canvas of its own so the eraser stays per layer; `renderPaintPng` gives the PNG of a document; `loadLayerImages` and `layerImageRefs` load what it names.
- **`paint/features.ts`** — `PaintFeatures`: `shapes`, `fill` (the bucket), `symmetry`, `eraser`, `layers`, `customColor`, `clear`, `select` (selecting, the lasso and moving the layer), `picker`, and `FULL_PAINT_FEATURES`. They only hide tools; a document drawn with a tool that is switched off keeps and draws its strokes.
- **`profiles.ts`** — `CanvasProfile` and the two shapes places start from, see [Profiles](#profiles).
- **`features.ts`** — `CanvasFeatures` and `FULL_CANVAS_FEATURES`: `arrange`, `align`, `guides`, `zoom`, `history`, `export`, `layers` (the element list), `group` (only for a place that stores `CanvasElement.group`; the Canvas and Altar blocks do, in their data JSON). What can be added is up to the registry.

### Elements and types

`CanvasElement` (`types.ts`) is the scene's unit: `id`, `type`, a frame shared by all types (centre `x`/`y`, box `width`/`height` before rotation, `rotation` in degrees around the centre, `opacity`, `locked`, `hidden`, `z` with higher on top and ties in list order), `ref`, which the place sets and the canvas editor only copies (the Canvas and Altar blocks keep a picture's stored file there), and `props`, which belong to the type.

A `CanvasElementType` says everything the canvas editor needs about a kind: `draw(ctx, el, env)` with the box's top-left corner at the origin (frame, rotation and opacity are the canvas editor's; `env.image(src)` gives a loaded picture, `env.time` the moment for moving types); `sources` and `fonts` it draws with; `animated` (redrawn every frame, such as a flame); `keepRatio` and `handles` (all eight, the corners, or the corners and the two sides); `scaled` (what else changes when a corner scales it, such as a font size or an outline); `fitHeight` (the height follows the props and width, kept current after every change with the top edge in place); `textEdit` (typing in place); `additions` for the tool column; `controls`, a component for the selected elements of the type. A place spreads its own types over `BUILTIN_CANVAS_TYPES`; a drawing from the paint editor, say, is a type whose `draw` paints the drawing into the box and whose `onEditElement` opens the paint editor, without the canvas editor depending on the paint module.

Each element is one Konva `Shape` whose `sceneFunc` calls `drawElement` with the node's live size, so a handle being dragged and the export draw alike; its hit area is its box. The artboard's background is DOM behind the canvas, scaled with the view, so a CSS background needs no drawing of its own; elements are clipped to the artboard.

### Interaction

- **Selecting.** A click selects an element, Shift, ⌘ or Ctrl adds or removes it, a drag on an empty spot draws a frame that selects what it touches, a click on an empty spot clears the selection. ⌘/Ctrl+A selects all. A click or the frame takes an element's whole group (`CanvasElement.group`); a double click on a member picks it alone, a second one opens it. Locked and hidden elements cannot be selected on the stage. While reading, a click selects one element and an outline shows it.
- **Moving** goes through `trackPointerDrag` and starts after `DRAG_THRESHOLD_PX`; it moves the whole selection and keeps every centre on the artboard. The canvas editor moves the Konva nodes itself during the gesture, without React, and commits once on release. Edges and centres snap to the artboard's and the other elements' (`snapToGuides`, within 6 screen pixels) and show a guide; with the grid's position snapping the grabbed element's centre snaps to the grid crossings instead. Alt moves freely.
- **Handles.** Konva's `Transformer` scales and rotates the selection, its handles from the selected types: pictures and text keep their proportions (Shift frees them), shapes do not (Shift keeps them). A single text also has side handles, which change its width and rewrap it live instead of stretching it (`fitHeight`); a corner scales its font (`scaled`). Rotation snaps to 0°, 90°, 180° and 270° nearby, to multiples of `rotationSnap` when it is given, and to 15° with Shift. With the grid's size snapping, an unrotated selection resizes in whole cells, its opposite edge staying put. On release the scale is baked into width, height (and font size) and the node's scale returns to 1.
- **Zoom and pan.** Pinching or ⌘/Ctrl with the wheel zooms at the pointer (5 % to 800 %), the wheel or two fingers pan, Space or the middle button with a drag pans. ⌘/Ctrl+0 and the toolbar fit the artboard again. Until the view is zoomed or panned it follows the viewport's size; while reading it always fits.
- **Keys** (on the focused stage, not while typing in a field): Delete or Backspace removes, the arrows nudge by 1 px (Shift: 10, with position snapping one grid cell), ⌘/Ctrl+D duplicates, ⌘/Ctrl+C, X and V copy, cut and paste (one clipboard for all builders in the window, each paste offset a little further; they also come as the `copy`, `cut` and `paste` events of the app's Edit menu, which on macOS takes the keys whenever text is selected somewhere), ⌘/Ctrl+[ and ] send backward and bring forward (with Shift to the back and front), ⌘/Ctrl+G groups the selection and ⇧⌘G ungroups it (with `group` on), Escape clears the selection, Enter types into a selected text or opens a selected element through `onEditElement`.

### History

`useCanvasHistory` keeps snapshots of the scene the canvas editor is handed — the element list and the `canvasBackground` (`CanvasScene`) — whoever changed it. The canvas editor's own gestures are one step each (`markLocal` before its `onChange`); changes from outside, such as a block's sidebar or the background panel, are steps too, except that a burst of them within 600 ms counts once (a slider). Undo hands the earlier elements to `onChange` and the earlier background to `onCanvasBackgroundChange`, each only if it differs; what the place hands back within 400 ms replaces it, so clamping or rounding there is not a new step. ⌘/Ctrl+Z, ⇧⌘Z and ⌘/Ctrl+Y, or the toolbar's arrows. The history starts over with `historyKey` and when editing starts or ends.

### Paint mode

A drawing element is painted in place. A double click or Enter on it, or adding one, enters the paint mode: the element's own node is hidden and `PaintSurface` lies over its box, the paint bar replaces the toolbar, and the handles go. The keys there are the paint tools' letters (V select, Q lasso, M move layer, P, L, O, R, G polygon, S star, B bucket, E, I picker), `[` and `]` for the size, ⌘/Ctrl+Z and ⇧⌘Z for undo and redo, ⌘A to select every stroke of the layer, ⌘C, ⌘X, ⌘V and ⌘D for the selected strokes, Delete to remove them and the arrows to nudge them (Shift: by ten); with zooming on, Space or the middle button pans and ⌘0 fits. Escape lets a selection go, then leaves; so do the bar's Done and a press beside the drawing. The mode also ends when the element goes (removed, undone) or is hidden. Every stroke and every layer change commits the element with its new document, so it is one step of the editor's one history, like a move; the brush stays as it was for the next drawing. A drawing whose layer images have not loaded yet cannot be painted on, since a save would lose them.

### Profiles

`CanvasProfile` bundles what a place offers: its element types (and with them what the toolbar can add), the editor's `features`, and the paint mode's `PaintFeatures`; a place spreads it over the editor's props. `fullProfile()` is everything: the built-in image, shape and text with a drawing type, and all tools. `paintOnlyProfile()` is the drawing type alone with nothing to add and none of the editor's tools but undo and zooming; with `paintElementId` on its one drawing, the editor is a plain paint editor. The concrete profiles live with the places, in their adapters.

### Paint document

`src/lib/paint/document.ts` holds the document, pure and DOM-free: layers from bottom to top, each with a name (empty: numbered by the editor), hidden or not, locked or not, an opacity, an optional image under its strokes with the rectangle it lies in (the whole page unless the layer was moved), and its strokes. A stroke has a tool (pen, eraser, line, ellipse, rectangle, polygon, star, fill), a colour, a size and flat `x, y, pressure` points in a fixed space of 1200 × 800; a shape keeps two points, and a box shape (ellipse, rectangle, polygon, star) a turn around its centre and whether it is filled, a polygon or star its corners. A fill keeps the spot clicked as its point and its area as closed rings of `x, y`, drawn even-odd and smoothed through the midpoints of their edges, sharp corners kept. The new fields are stored only when they differ from the default, so older documents read unchanged. The geometry lives here too: `applyTransform` and `transformStroke` (a move, a uniform scale and a turn around a pivot, baked into the points and the width), `strokeBounds`, `translateLayer`, `mirrorStroke` and `symmetricCopies` (mirrored, four quarters or turned around the page's middle; every stroke is committed together with its copies, as one step, and the copies are strokes of their own), and the layer changes `copyLayer`, `mergeDown` and `moveLayerTo`. `paintDocToJson` stores it with short keys, coordinates rounded to a tenth and pressure to a hundredth; `paintDocFromJson` checks and bounds everything (16 layers, 10,000 strokes, 1.5 million numbers) and drops what it cannot read. A layer's image reference is not in the JSON: the storing place keeps it where image references are found (an `<img src>`), so backups, exports and the image cleanup see it, and hands it back by layer ID. An image as a layer is how a drawing from before the vector format is kept whole: the eraser takes from it like from the strokes.

### Canvas blocks

`CanvasBlock` is the adapter of the canvas block (see [Blocks](blocks.md#canvas-block)). It opens the canvas editor inline with `fullProfile`, less the additions of the parts the block switched off, with the swatches as palette and the vault's own symbols. The editor's `onInsertImage` puts a button in the tool column; the block opens the picture picker and places the chosen pictures in the middle of what is visible. With "Images" below (an altar's default), `ImageStrip` stands below it, two rows that scroll sideways under a head with the search: the pictures of "Images" to search, drag out (the `imageDragState` channel, dropped where `clientToArtboard` lands) or click (placed in the middle of what is visible), each in its own proportions at a third of the artboard's shorter side. A tag in the strip's head narrows it down; it is saved in the block's config next to the parts (`tag`, `withCanvasStripTag`; '' for all, "×" sets that), and an altar block without one starts with `ALTAR_LIBRARY_TAG_ID`. Its "+" opens `AddImagesModal` with that tag set; an "Altar Library" the vault does not have yet is made by name with the first picture added (`tagForNew`). Files from the disk let go over the block are stored, taken into "Images" under their file name, with the strip's tag, and placed where they were let go (while the add dialog is open, they go there); the block carries `data-file-drop`, so the text editors' own drop leaves them alone (`dropClaimedAt`). The background picture is chosen with the picture picker.

### Altars as operations

An altar is an operation of the built-in category Altars (id `altars`, 🪔) whose content starts from the built-in template `core-altar`: an Altar block on a night background and a text block for notes. There is no altar module, table or store of its own. Altars of older vaults, backups and `.emerald` files are converted by `convertAltars` (`src/lib/altarConversion.ts`), which migration v62, the backup import and the `.emerald` import share:

- **Altar → operation** under the altar's own ID, so links, tasks and devices that convert the same altar arrive at the same row; numbered on from the last operation, in the Altars category, with title, icon, dates and trash state of the altar. Its content is an Altar block (block IDs derived from the altar's ID, `altarBlockIds`) and an empty text. The scene: the placements and the drawn elements (`placementToElement` in `src/lib/altarScene.ts`, `parseAltarElements` in `src/lib/altarElements.ts`) at the altar's resolution (`resolveResolutionPixels`, `src/lib/altarConstants.ts`), its background (`altarCanvasBackground`, `src/lib/altarBackground.ts`) and its guides (`parseAltarSettings`, `src/lib/altarSettings.ts`). The grid has no place in the block and goes. A placement of an item in the trash is left out.
- **Library item → picture of "Images"** under the item's ID, with its name and note, in the trash if the item was; a picture still inline (Base64) is stored as a file first. One picture per file, an active item winning. An item without a picture (an emoji) stays on the canvas as its emoji; a candle (`isCandleEmoji`) still flickers.
- **Links** follow: altar chips in entries and templates point at the operation (`contentWithAltarsAsOperations`, the ID stays), altar fields and altar defaults of block definitions become link fields (`elementsWithAltarsAsOperations`), and task links to an altar become links to the operation.

`src/lib/migrateAltars.ts` runs it inside the vault: v62 (`altarsToOperations`) converts and empties the altar tables, v63 (`dropAltarTables`) converts whatever an older device synced in since, drops the tables and removes their rows from `_sync_log`. Each takes a copy of the file first. For the imports see [DB Backup / Restore](../database.md#db-backup--restore-emeralddb) and [Emerald Format](../features.md#emerald-format).

### Sigil drawings

`DrawingBlock` is the adapter of the paint block (`core.paint`, `PaintBlock`, in the canvas swatches) and of the sigil drawing (`SigilCanvasBlock`, which puts its concealment and lock around it and brings the sigil palette and a part's starting brush). It opens the canvas editor with `paintOnlyProfile`, inline, on a scene of one locked drawing over the whole 1200 × 800 artboard, fixed in its paint mode (`paintElementId`): to the user a paint editor with its bar over the sheet. The document comes from the block (`parseDrawing`; a drawing from before, or one whose first image is not marked as the rendered one, becomes a document with that image as its only layer), with the palette and starting brush its block hands in. Layer images are loaded as data URLs first, since the stored PNG is rendered from them; if one cannot be loaded the block says so instead of offering an editor whose next save would lose it. It saves 300 ms after the last change, and when the editor closes whatever is still waiting: the PNG (`renderPaintPng`) goes to `saveImage`, and `withDrawing` writes the document as data JSON and the HTML with the rendered image first (`data-paint="render"`), then each layer's image (`data-paint="<layer ID>"`). The stored form is the same as before the canvas editor; read mode, the entry's card and the exports show the rendered image.
