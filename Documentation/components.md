# Components

The app's shared building blocks and the rules for when to use them. This file is a **specification**, not an inventory — it answers "does this already exist?" and "may I deviate here?".

For the *look* of these building blocks (colour values, radius, icon sizes, theme classes) see [`design.md`](design.md). For their place in the module tree see [`architecture.md`](architecture.md). What is recorded here is the contract only: what a building block encapsulates and what the caller supplies.

## Rule

**Search first, then build.** Before every new component, every new Tailwind class-chain recipe and every new utility function: check the catalogue below.

**A deviation needs a reason in the code.** Not in a commit message and not in this file, but as a comment at the place that deviates. Whoever trips over it in a year reads the code, not the history. The sections [When Deviating Is Right](#when-deviating-is-right) and [Known Duplication](#known-duplication) are the exceptions that already have this scrutiny behind them.

**A third copy means centralise.** Two similar places are not yet duplication — at the third it is established that this is a pattern and not a coincidence. Abstracting earlier produces a component that fits nobody.

## Chrome Principle

Every shared building block here standardises **the shell, not the content**: frame, surface, position, open/close, keyboard behaviour. What goes inside stays the caller's business.

The escape hatch is therefore **part of the contract, not a loophole**. Using it does not bypass the component — it uses it as intended:

| Building block | Escape hatch | Intended for |
| --- | --- | --- |
| `Modal` | `children` | the entire dialog content |
| `EmojiPicker` | `trigger` render prop | the trigger looks completely different per context |
| `Dashboard` | `renderItem`, `grouping.mode='custom'` | item look, respectively a structure that cannot be grouped |
| `EntryListTab` | `renderRow` | a row that is not an icon row (Tasks' checkbox) |
| `DashboardItem` | `children` | `RowContent` or `CardContent` inside the clickable frame; while renaming, a `RenameField` as the title |
| `InlineNameEditor` | the caller's row around it | the leading glyph (emoji picker, colour dot) and the placeholder that keeps it aligned with the read row |
| `EntryDetailFrame` | `children` plus the `meta`/`aboveTitle` slots | everything below the shared header-row/title/tag shell — the entry's own body and its cover |
| `Button` | `className` is **appended**, not replaced | layout and spacing per call site |

The converse holds too: a shell you end up overriding completely is the wrong shell. If `className` on a `Button` undoes half the variant, a variant is missing — and it belongs in `Button`, not in the caller.

## Catalogue

Each entry: what it is and when to use it, then its extension points (*Ext.*).

### `src/components/ui/` — Shared Components

**Actions and confirmation**

- **`Button`** — **every** action button. Five variants (`primary`/`primaryDanger`/ `secondary`/`ghost`/`danger`; `primaryDanger` is `primary`'s shape in red, from the `--danger-solid-*` tokens) plus a tinted row-action mode (`tone`: `jade`/`amber`/ `danger`/`neutral`). *Ext.:* `className` (appended), `compact`, `small` (tone mode only — 24px instead of 30px for dense rows such as category headers; its icon belongs on the 12px step), `fill`, `active`.
- **`InlineConfirm`** — the "Sure? Yes, delete / Cancel" confirmation in place of a row's actions. When it shows is the caller's business (a `confirming…` state); `onConfirm` only executes. Use it where nothing can be undone (the Trash); deletes that land in the Trash with an undo toast need no confirmation — except a warning when the delete reaches beyond the item: a tag still on entries (Tags, `tags.deleteWarning`), like a picture still shown in texts, which asks the same in its own dialog footer. *Ext.:* `message`, `confirmLabel`, `tone` (`danger` default, `jade` for a confirmation that changes rather than deletes), `small` (24px buttons), `wrap` (for the right sidebar's narrow column), `variant: 'banner'` (full-width strip on the `--danger-bg`/`--danger-border` tokens for dialogs; always a delete; currently no caller).

**Overlays and menus**

- **`Modal`** — overlay, card with frame and sheet, header with close X that also moves the modal within the window, `createPortal`, escape-to-close. Escape belongs to the topmost open modal only (a module-level stack): a second modal over the first — the unlock question over another dialog — closes alone, and a non-dismissible one on top swallows Escape for those below. *Ext.:* `children`; `dismissible={false}` removes all three ways to close at once; `footer` (the action row, right-aligned and pinned under the body; a delete on the far left takes `mr-auto`); `className`/`bodyClassName`/`widthClassName`/`maxHeightClassName`.
- **`EditDialogFooter`** — the footer of a dialog that edits one thing (category, symbol, picture, a dashboard's settings): Delete on the far left (only with `onDelete`), Cancel, Save. *Ext.:* `onDelete?`, `onCancel`, `onSave`, `saveDisabled`.
- **`ContextMenu`** — right-click menu: portal, edge logic, closes on click and Escape in the capture phase, so a menu above a `Modal` doesn't also close the modal (whose Escape handler hangs off the same `document`). A row's `onMouseDown` cancels default, so an existing text selection survives the click (needed for `EditContextMenu`'s Cut/Copy). The menu is `w-max`, so it never shrinks against the window edge while being measured. *Ext.:* `actions: ContextMenuAction[]` (each with `icon`, `danger`, `disabled` — dimmed via opacity, `separator` — a line above it, `shortcut` — a key shown at its end, `checked` — a checkmark entry whose tick takes the icon's place), `align="right"` (`x` is the right edge — the edit sidebar's value-button menus), `minWidth` (default 160).
- **`EditContextMenu`** — the app's own right-click menu for text, built on `ContextMenu`: Cut/Copy/Paste/Select all in an editable field, Copy on selected read-only text. The native menu stays for the rich-text editor (spell-check suggestions can't be reproduced from JS) and for any element whose own handler called `preventDefault`. Rendered once in `App.tsx`, beside `AppShell` rather than inside it, because `AppShell` returns early for the vault picker. Reuses the title bar's `editCommands.ts` and the `menu.*` i18n keys. *Ext.:* none.
- **`EmojiPicker`** — emoji popover on the menu tokens: open/close, portal, `SearchField` for a search across the full localised emoji set, the chosen emoji in jade, outside click, Escape in the capture phase. *Ext.:* `trigger` render prop, `emojis` (default: the vault's own set from Settings → Entries, falling back to `DEFAULT_EMOJI_PICKER_EMOJIS`; pass it explicitly to bypass the vault's set, e.g. the vault picker's icon picker), `align`, `size`.
- **`Dropdown`** — generic themed dropdown menu (`CategorySelect`, `TaskRow`'s priority menu, block field values, …). *Ext.:* `trigger` render prop (the `EmojiPicker` convention), `portal` (fixed position, opens upward when short on room — needed inside the right sidebar's overflow container), `label`, option `emoji`/`icon`/ `className`, option `disabled`/`title`, `align`.
- **`FieldDropdown`** — a `Dropdown` in the properties-field look: full width, field-frame border, trailing chevron, always portalled (the sidebars scroll). Used by the sort select of `ListToolbar`. *Ext.:* `value`/`options`/ `onChange`, `triggerText`, `align`, `variant="sidebar"` (selected option's `icon` leads, 13px text, `ChevronsUpDown` — lines up with the `SwitchRow`s below), `ariaLabel`.
- **`CategorySelect`** — the themed category picker, built on `Dropdown`. Its list opens with "Uncategorized", a real value (`null`): what a new entry carries, and picking it clears an assignment. Its trigger is an inline chip (`TaskRow`). *Ext.:* `align`, `title`.
- **`TemplateSelect`** — the template picker, built on `Dropdown` like `CategorySelect`: "none" (`null`) and every active template; a template in the Trash or gone shows as none, the rule `resolveStartTemplate` applies. The vault's default template, and a category's start template in the Templates view (`CategoryStartTemplatesSection`). *Ext.:* `label` (optional chip prefix), `noneLabel`, `value`, `onChange`, `portal`.

**Global singletons** — rendered once, in `AppShell` (the export menu and the import window in `LeftSidebarRail`, which is mounted once too); never add them per view.

- **`UndoToast`** — global undo toast, fed from `undoStore`. The store holds **one** action, the latest; a new `push` replaces it (older deletions are restored from the Trash). `dismiss()` also runs on a vault switch, because the action restores rows by id in whichever database is open.
- **`SaveNoticeToast`** — the one notice for a change that could not be written to the database ("Could not save the change — it was undone."), fed from `saveNoticeStore`; `reportSaveError(err, context)` logs and shows it. The reporting store has put its state back first (dashboards do; see [Dashboards](architecture/modules.md#dashboards)), so the notice never has to explain a half-saved state. Once in the AppShell, mounted next to `UndoToast` and in the same screen corner, so the two can overlap.
- **`layout/LeaveGuardModal`** — the question when a page with unsaved edits is left (Keep editing / Discard / Save), fed from `store/leaveGuardStore.ts`. A page takes part by registering a guard (`useEditActions`' `guard`, or `useDraftPage`), never by rendering its own dialog.
- **`layout/VaultKeyDialog`** — the password question in front of every vault: set a password (new vault), unlock, and recover with the recovery key. Fed from `store/vaultKeyStore.ts`; a caller asks through `ensureVaultReady`, never by rendering the dialog. Its building blocks `RecoveryKeyBox` (shows a new recovery key until the user confirms it is stored) and `vaultKeyParts.tsx` (`KeyField`, `NewPasswordFields`, `newPasswordProblem`, `keyErrorText`, `onEnter`) are shared with Settings → Security — any new password field uses them. See [`architecture/encryption.md`](architecture/encryption.md#the-unlock-gate).
- **`layout/BackupUnlockDialog`** — asks for the secret of a protected `.emerald` file: its own password, or — for a file under a vault key no open vault has, such as a `.vault.emerald` backup — that vault's password or recovery key. Fed from `store/backupSecretStore.ts` (`askBackupSecret`, called by `openArchiveAsking`); also for a raw backup, whose vault key it unwraps.
- **`layout/import/ImportModal`** — the import window, the export menu's counterpart, mounted by `LeftSidebarRail` from `store/importWindowStore.ts` (the title bar's Import, or a drop through `useImportDrop`): a `.file-drop-zone` to drop on or click, then what the file is (`openImportFile`), and its choices under the same Normal/Advanced `SegmentedControl` and `Part` layout as the export menu (`Part` and `Checklist` in `layout/menuParts.tsx`) — the item list on `Checklist`, the destination on `FieldDropdown`, existing items on a `SegmentedControl`. A database file's part is `useVaultImport` (new vault, merge or replace as `SettingsChoiceButton` cards, the replace warning in the danger tokens, Advanced's `EntryCategoryChecks` and `SettingsCheckboxGrid`). Its remembered choices are in `lib/importFile.ts`. The window holds the opened file and lets go of it when another comes or it closes.
- **`layout/export/ExportMenuModal`** — the export menu, mounted by `LeftSidebarRail` from `store/exportMenuStore.ts` (the title bar's Export opens it with the entry or template on screen): scope, level, format, protection and the PDF/HTML font size on `SegmentedControl`s; the collection's dashboard and the font on `FieldDropdown`, its own filter on `FilterList` and `TagInput` with `existingOnly` (a filter picks existing tags; a typed new name creates nothing); the new password on `NewPasswordFields`. Its rules — what it remembers, the fixed Normal settings, period and order — are in `lib/exportMenu.ts`, the selection by `matchesFilter`. `ExportEntryChecklist` is its list to tick entries off (`BlockCheckbox` rows, on the shared `Checklist` of `layout/menuParts.tsx`, which the import window uses too), `VaultExportOptions` the whole database's Advanced choices (`EntryCategoryChecks`, `SettingsCheckboxGrid`).
- **`SearchField`** — the outlined search field of the overlays: magnifier, input, clear button, focus ring. Global search, link picker, emoji picker, the picture picker, the canvas editor's symbol library, the Settings' emoji defaults and the rail's plus window (`CreateItemModal`). Not the entry list's borderless field on the frame, nor `ListSearchField`, the field on a page. *Ext.:* `value`, `onValueChange`, `inputRef`, `className`/`style` for the field, every other prop goes to the input.
- **`ImageNoticeModal`** — the one notice for an image insert that didn't happen (wrong format, or too large after scaling to the vault's limits), fed from `imageNoticeStore`. Covers every insert path without a notice line of its own (paste, drop, toolbar, a field block's image slot). Call sites use `useImageNoticeStore.getState().show(notice)` or `reportImageError(err, context)`.
- **`DashboardSettingsHost`** (`views/DashboardSettingsModal.tsx`) — the one settings dialog of a dashboard: name, icon (`Favicon`), the category filter (`FilterList`, "All" meaning no category rule, with a field that creates a category and ticks it), the tag filter (`TagInput` with `drafts`, so a typed new tag is created by `commitDraftTags` on Save, not at once), Delete (into the Trash with undo), Save/Cancel; "All entries" gets neither filter nor Delete. Opened through `openDashboardSettings(id)` (`store/dashboardSettingsStore.ts`), never rendered per view.

**Dashboards**

- **`Dashboard`** — chrome of the overview screens: every entry dashboard (through `EntryDashboard`), every collection (through `CollectionDashboard`), Tasks and Trash. Owns title, search, actions, toolbar, filter, grouping, empty state.
  - *Layout:* title (the title alone — no icon, no count) and search (`ListSearchField`) sit inline in one row above the content. Actions, `ListToolbar` and `FilterPanel` live only in the right sidebar, portalled via `SidebarPortal`; closing the sidebar removes those, while title and search stay — see [Architecture → List Header Portal](architecture/editing.md#list-header-portal).
  - *Header:* `title`. `view`/`sort`/`onView`/`onSort` are optional — a view with neither axis gets no toolbar row.
  - *Items and grouping:* `renderItem`; `grouping` (`flat`/`timeline`/`category`/ `custom`); category mode's `isGroupCollapsed` (a collapsed group renders only its header; the chevron lives in the caller's `renderGroupHeader`). Category mode drops empty groups centrally. `sortModes` narrows or extends the sort choice; `groupBy` (`{ value: GroupingMode, onChange, label? }`) adds the grouping axis, independent of `sort`; `displayToggles` adds preferences under the view section.
  - *Actions:* `primaryAction` (`DashboardPrimaryAction`: a labelled button filling the `SidebarActionBar` — jade with "+" by default; `danger` makes it the red `btn-primary-danger`, `icon` replaces the "+", `disabled`). Trash's "Empty trash"/ "Delete selected" confirm there: the label turns into "Yes, …", clicks within 400 ms of arming are ignored so a double-click can't pass it, and a cancel X joins via `extraActions`. `extraActions` are compact icon-only `neutral` buttons beside it (label in a tooltip), for the selection (Trash's restore and select all) or cancelling a confirmation.
  - *Sections:* `contentHeader` / `contentFooter` render above/below the content, also in the empty and no-results states — a heading for the main list, or a second area of the module (Blocks' read-only built-in blocks). Their heading is `CollapsibleGroupHeader`, like every other. 
  - *Grids:* `cardsClassName`/`wideCardsClassName` — separate props, since a module may fill the wide card differently.
  - *Empty and no results:* `emptyState` renders `EmptyState`, its icon the view's rail icon (`TASKS_VIEW.icon` / `AUX_VIEWS[id].icon`); `hasNoResults` and a category mode with no surviving group render `NoResults`, using `search`/`onSearch` and `filters.onClearAll`.
- **`DashboardItem`** — a clickable item inside a `Dashboard`: the `panel-interactive` frame (`layout: 'row' | 'card'`); click opens `view` via `setActiveView`, middle-click via `openViewInNewTab` — or, given `onOpen` instead of `view`, a click runs that (an item that opens a dialog: a category, a picture, a symbol). With `editing` it renders the same frame as a plain `div` without its handlers, for in-place renaming with `RenameField` (`RENAME_INPUT_CLASS`). `.panel-interactive` carries its own `:focus-visible` ring in both theme blocks. *Ext.:* `view` or `onOpen`, `layout`, `onContextMenu`, `editing`, `children`. Same file:
  - **`DashboardRow`** — the same row as a `div`, for rows whose click is the caller's (a tag that expands, a task, a trashed item). `.row-selected` marks a selected one. *Ext.:* every `div` attribute; `className` is appended; no `onClick` means no pointer cursor.
  - **`RowContent`** — the inside of the one row: symbol, name, metadata on the right. *Ext.:* `icon`, `title`, `meta`, `info` (parts after the metadata, each after a "·", never cut — the metadata shortens first).
  - **`CardContent`** — the same three stacked for a card. *Ext.:* `icon`, `title`, `meta`, `info` (a wrapping line of its own below the metadata), `children` below them.
  - **`CardTags`** (`ui/CardTags.tsx`) — an entry's tags in one line under a card, as `CardContent`'s child: only whole chips, the rest as "+N" with the hidden names in its tooltip; if not even the first fits beside "+N", it stays, shortened. *Ext.:* `tags`. Same file: `chipStyle(color, dashed?)`, a tag chip's colours (with a `border` class), shared with `TagInput` — `dashed` for a tag a block gives.
  - **`RowSymbol`** — a row's symbol column, for a row that sets out its name itself. `ROW_GEOMETRY_CLASS` is the row's shape, for a resting row without the frame (Blocks' built-in ones).
  - **`ItemGlyph`** — an entry's icon, emoji or image. *Ext.:* `icon`, `large` (card size).
- **`EntryDashboard`** (`views/EntryDashboard.tsx`) — the one entry list over a dashboard, on `Dashboard`: search, category filter, grouping by category, list/cards/timeline, context menu, rename, empty state, view and sort through `useDashboardPrefs`. `DashboardView` shows every dashboard through it; each entry is drawn by `entryIcon` and opens on the entry page inside this dashboard. `dashboardSettingsAction(t, id)` is the settings icon button beside "New …" (`extraActions`) that every entry dashboard carries. *Ext.:* `dashboard`, `title`, `newLabel`, `onNew`, `emptyState`.
- **`CollectionDashboard`** (`views/CollectionDashboard.tsx`) — the one display of every collection (Tags, Categories, Images, Templates, Blocks, Lexicon, Symbols), on `Dashboard`: search, filter chips, sort and view, a context menu. The caller says what an item is — `itemTitle` (name sorts and search), optional `itemDate` (date sorts, the timeline unless `noTimeline`), `itemCount` ("most used"), `manualOrder` (the items' own order as sort `manual`), `matchesSearch` (what else the search looks at), `filter` (`CollectionChip`s, each with its `test`; an item passes on any selected one, with `match: 'all'` on every one — Images) — and how it looks: `describe` (icon, card icon, title, meta, trailing, and `view` or `onOpen`). `renderItem` replaces one item (a picture tile, a tag being renamed; `undefined` falls back to `describe`); `renderList` draws the list view itself (Tags' expanding rows, Categories' drag handles) and gets the searched, filtered, sorted items, the context-menu opener and the sort in effect — empty and "No results" stay here. `collapsed` and `loading` show nothing below the heading. `itemAttribute` puts a data attribute with the key on every item, cards included, for a deep link to scroll to; `highlighted` marks the target with `row-target`. The state comes from `useCollectionState(id)`: view and sort per vault in `uiStore.collectionPrefs` (a value the collection does not offer falls back to its first), search and filter for the session under `collection:<id>.*`, with `query` (trimmed, lower case) and `reset()` (clears both). The ids are `COLLECTION_IDS` in `lib/modules.ts`. *Ext.:* the above, `primaryAction`, `emptyState`, `contentHeader`/`contentFooter`, `cardsClassName`.
- **`DashboardSection`** — a second area below a dashboard's list: a `CollapsibleGroupHeader` that collapses it, remembered per key. Blocks' built-in blocks, the default template, the Lexicon's translate panel. *Ext.:* `storageKey`, `label`, `children`.
- **`EmptyState`** — the one empty state of a dashboard or one of its sections (designer's pattern "1b"): no box, a 44px icon tile, an 18px title in the entry-title font, one 13px sentence saying what belongs here (not that it is empty), a 30px neutral "+ New …" button. Placed at the top of the content, not vertically centred, so nothing jumps when the first item appears. Texts live under `emptyState.<view>.title/description`. A dashboard's other sections stay visible when it is empty. Rendered by `Dashboard` and directly by custom-mode views and sections with their own empty case (Tasks, Trash, the Lexicon's translate panel). The left entry list has its own two-line version in place of the first row. *Ext.:* `icon`, `title`, `description`, `actionLabel` + `onAction` (both or no button), `actionIcon` (default `Plus`), `className`.
  - **`NoResults`** (same file) — the same layout for "search/filters left nothing": `SearchX`, a sentence naming the query, "Reset filters" clearing search and filters at once. *Ext.:* `query`, `filtered`, `onReset`.
- **`ListToolbar`** — the view/sort/grouping sections of `Dashboard`'s sidebar header, each under a `label-xs` heading, always in this order. Every axis is optional; with none, it renders nothing. View: `IconToggleGroup` with `fill` (List/Cards/Cards-wide/Timeline), then the `displayToggles` as `SwitchRow`s (view preferences, not counted in `activeFilterCount` and left alone by a reset). Sort: `SortSelect`; in the Timeline a blocked sort (name/count) shows as newest first while the stored sort stays and applies again when the layout is left. Grouping: a `SwitchRow` "Group by {label}" (default "category"; en/es/fr lowercase it via the `lowercase` i18n formatter), greyed out in Timeline. *Ext.:* `sortModes` (default the four date/name modes; `count_desc` and `manual` where a collection offers them), `sortDate` (`SortDateField`: `created`/`updated`/ `deleted`), `displayToggles`, `subSort` (`SubSort`: a second sort under its own heading, for what is listed under each item — the entries under a tag; `Dashboard` and `CollectionDashboard` pass it through, the latter only while its `renderList` draws).
- **`ListSearchField`** (exported from `ListToolbar.tsx`) — the search field on a page: a dashboard's, rendered by `Dashboard` in the main area beside the title, and `ImageStrip`'s. *Ext.:* `value`/`onChange`, `placeholder`, `className` (width — `Dashboard` passes `w-[260px]`).
- **`FilterPanel`** — the always-visible filter column under `ListToolbar`. Order: the primary `FilterList` (`chips`, `chipLabel`, `onAllChips` + `allChipsCount`), a second one (`statusChips`, `statusLabel`, `onAllStatus` + `allStatusCount` — Tasks' priorities). No "clear all": each list's "All" row clears it. *Ext.:* `FilterPanelProps`, passed through as `filters.panelProps`; `activeFilterCount`/`onClearAll` sit beside it on `filters` and only back the no-results reset.
- **`FilterList`** — a filter as a vertical list: icon or emoji, label, count; an "All" row on top (`Asterisk`, total). Multi-select; "All" is active while nothing is selected and clears the selection. Rows are `.filter-row`, counts dimmed at 0. *Ext.:* `chips: FilterChip[]` (`{ value, label, emoji?, icon?, count?, hint? }` — `hint` is the row's tooltip, for a label that is short on purpose; count over the list after search but without this filter, so it holds still while toggling), `selected`, `onToggle`, `onAll`, `allCount`, `label`. Its row, **`FilterRow`**, is exported for a choice from a list in the same look (a category's start template; the categories on a template's page), with an optional quiet `detail` after the label.
- **`IconToggleGroup`** — a bordered row of icon buttons, one segment per option, active one filled, no visible label (aria-label and tooltips). The dashboard view row. *Ext.:* `fill` (full width, equal segments), `isDisabled` + `disabledHint`, `value: null` for a mixed state.
- **`SegmentedControl`** — a choice among a few options as segments on an inset track (`.prop-segments`), the active one in jade: the canvas editor's export dialog and background panel, the dashboard settings' info line (short/detailed). An option with an `icon` shows only the icon, its `label` as tooltip and accessible name; one without shows the label at the width it needs (`.prop-segment--label`). Unlike `IconToggleGroup` it sits on a field's inset track, for a value inside a panel or form rather than a view switch. *Ext.:* `options` (`{ value, label, icon? }`), `value` (`null` when none holds — a size typed in by hand), `onChange`, `ariaLabel`, `disabled` (all segments), `className` (appended to the track).
- **`TabIconButton`** — active/idle toggle behind `IconToggleGroup`'s segments. *Ext.:* `active`, `compact` (26px instead of 30px), `disabled` (with `title` — deliberately keeps pointer events so the tooltip still shows).
- **`ProgressBar`** — a thin accent bar with an optional label to its right (`role="progressbar"`). `percent` `null` leaves the bar empty rather than guess; the label shows it is still running. The update download (`StartUpdates`) and re-encryption (`ReencryptProgressLine`). *Ext.:* `percent`, `label`.
- **`SwitchRow`** (around the file-local `Switch`) — an on/off switch (`role="switch"`, `.switch`, thumb colours `--switch-thumb`/`--switch-thumb-on`; on is a muted jade track, not the full accent) and a row of icon, label and switch where the whole row is the label. For settings that take effect immediately (dashboard sidebar toggles, a block page's "Display", the Settings window's Entries page). A block's yes/no field (`ToggleSwitch` in `FieldValueEditor`) stays separate: there the value is content, not a control. *Ext.:* `checked`, `onChange`, `disabled`, `title`; `SwitchRow` adds `icon`, `label`, `hint` (a wrapping muted line; the switch aligns with the first text line), `variant` (`sidebar`: indented like the edit sidebar's rows, hover surface; `panel`: flush with the fields above, no hover).
- **`CollapsibleGroupHeader`** — the **one** heading above rows on a dashboard, 24px tall: chevron, fixed `w-5` emoji column, label (a click on it collapses too), `count`/`meta`/`actions` slots, and a jade "+" that creates an entry in that group. Category groups in the dashboards and Tasks, their "Uncategorized" buckets (no "+" — nothing can be created in a trashed category), the months of a timeline, the types in the Trash, whole sections (custom blocks, templates, Languages). *Ext.:* `onToggleCollapse` (omit for a non-collapsible header), `collapsed`, `emoji`, `count` (renders "(n)"), `add` (`{ title, onClick }` — one prop so the icon button cannot lack an accessible name; `Button`'s tone mode at 24px), `meta`, `actions`.
- **`CollapseChevron`** — the one collapse/expand arrow. *Ext.:* `collapsed`, `onToggle`.
- **`ModuleCounts`** — usage counters for entries and tasks: icon plus number, dimmed at 0, the name in the tooltip (`CategoriesView` and `TagsView` rows). *Ext.:* `modules` (`CONTENT_MODULE_IDS` or a part of it, fixed column order, so numbers line up), `counts`.

**Entry list, detail frames, renaming**

- **`EntryListTab`** — rows of the left entry list: search (a borderless row on the frame, flush with the sheet's top edge), empty state, inline rename, drag start, context menu. Creating is the rail's plus and the module's own dashboard, not this list. *Ext.:* `getId`/`getTitle`/`getEditTitle`/`getIcon`/ `getDateStr`, `getInfo` (short additions at the end of the date line that keep their width), `onDragStart` (all-or-nothing per config — every module is a link target), `contextMenuActions`, `renderRow`. `getTitle` is what a row shows (`displayTitle`); `getEditTitle` is what renaming starts from (the stored title) and defaults to `getTitle`, so a caller with untitled entries must pass it or Enter would save the placeholder.
- **`EntryDetailFrame`** — the frame of the entry page (`EntryView`): header row (`EntryHeaderRow` — back link to the dashboard the entry was opened from, plus date, or `EntryStatus` while editing/unsaved), title block (input ↔ `h1` showing `displayTitle`, placeholder "Untitled entry", both on `ENTRY_TITLE_HEADING_CLASSES`), optional read-only tag row, and a body that always scrolls in the frame (`BlockStack`'s sticky toolbar needs the frame to be the scroll container). Edit mode is entered only via the right sidebar's Edit button. `EntryHeaderRow`, `EntryStatus` and `ENTRY_TITLE_HEADING_CLASSES` are exported for `LibraryPageFrame`. *Ext.:* `dashboard`, `meta`, `aboveTitle` slots.
- **`LibraryPageFrame`** — the detail-view frame of a library page (a user-built block, a template, a language): the same `EntryHeaderRow` shell, name-as-title input, scrolling body, and the right sidebar's column portalled via `SidebarColumn`. The frame owns the shell; what stands in the sidebar's action bar is the page's business. *Ext.:* `draft` (`{dirty, busy, onDone, onCancel, onDelete, markUnsaved?}` — a page that saves only on "Done". It adds the status above the title, `EditActionBar`, and Done/Cancel above the title while the sidebar is closed. The status reads "Editing…" and turns into "Unsaved" once dirty; `markUnsaved: false` keeps "Editing…" throughout, like an entry) **or** `read` (`{onEdit, meta?}` — the read view of a page that has one, a language: the name as heading, `meta` top right, `EditModeBar`); `backLabel`/`onBack`, `name`/`nameLabel`/`namePlaceholder`/`onNameChange` (edit only), `sidebar`, `children`.
- **`useEntryRows`** (`hooks/useEntryRows.tsx`) — the one row of an entry, wherever a list shows one (the left list, a dashboard, the entries under a tag): icon value (`entryIcon`), title, the info line (`meta`: category · the date the list sorts by; `narrowMeta` for the left list, without the category while the blocks add something; `info(entry, form)`: what the entry's blocks add, one never-cut node per part — short as icon and short value with the long form as tooltip, long as "Label: value" — see [Blocks](architecture/blocks.md#registry-and-interfaces)), where it opens (`entryView` in `dashboardId`, else "All entries"), rename, drag start, and the context menu (Open in new tab, Duplicate, Save as template, Rename, Delete with Undo). The frame is the list's: `EntryListTab` in the left list, `DashboardItem` in the main area. *Ext.:* `dashboardId`, `dateField`. Same file: **`useEntryItems(rows, entries, form?)`** — the main area's entry rows, with the blocks' info line in `form` (a dashboard's setting, long elsewhere): `render(entry, 'row' | 'card', below?)` draws the `DashboardItem` with `RowContent`/`CardContent` and in-place renaming, `menu` is the context menu to put into the view once.
- **`RenameField`** — the in-place rename input: Enter and blur commit, Escape cancels. The title of a `DashboardItem` with `editing`. `EntryListTab`, `LeftSidebarEntryList` and `TaskRow` still carry their own copy. *Ext.:* `value`/`onChange`, `onCommit`/`onCancel`, `className` (the caller's type styles).
- **`InlineNameEditor`** — body of a one-line name editor: input (Enter saves, Escape cancels), error text, jade Save and neutral Cancel icon buttons. A bare fragment — `TagEditRow` wraps it with its own leading glyph. *Ext.:* `value`/ `onChange`, `error`, `onSave`/`onCancel`, `placeholder`.

**Right sidebar shell**

- **`SidebarColumn`** — the shell of a right-sidebar column: a `bar` on top, the scrolling `p-3` body below. The one place the column's horizontal inset is set — a panel adding its own `px-*` would misalign its rows against the bar's `px-3`. Used by `RightSidebar`, `Dashboard`'s header and the library pages. *Ext.:* `bar`, `bodyClassName` (appended).
- **`SidebarActionBar` / `EditActionBar` / `EditModeBar`** (in `SidebarColumn.tsx`) — the 56px bar at the top of a `SidebarColumn`, with a divider under it (`.sidebar-divider` on `--sheet-border`): it sits on the sheet, unlike the entry list's tighter search row on the frame. `SidebarActionBar` is the bare `px-3` row; `EditActionBar` is Done/Delete/Cancel inside one (edit mode and every draft library page): "Done" is the one filled primary action (`.edit-bar-done`, `--control-h` tall), Delete and Cancel are squares beside it (`.edit-bar-icon`). `EditModeBar` is the read view's amber "Edit" filling the bar (an entry, a language); `lockedTitle` disables it and says why. *Ext.:* `children`; `onDone`, `onDelete` (omit for no Delete), `onCancel`, `busy` (disables Done while saving), `locked` (disables all three — `uiStore.editLocked`, see [Cancel](architecture/editing.md#cancel)).
- **`SidebarGroup`** (in `SidebarColumn.tsx`) — a labelled section of the sidebar body: `label-xs` heading, `role="group"`. *Ext.:* `label`, `children`.
- **`SidebarPortal`** — renders into `uiStore.listHeaderHost`, or nothing if the sidebar is closed. Read by `Dashboard` and the library pages; `MainArea` renders one view at a time, so only one is ever mounted. *Ext.:* `children`.
- **`RailButton`** — icon buttons of the left rail and the title bar, a thin wrapper around `.btn-ghost`. *Ext.:* full `ButtonHTMLAttributes`, plus `active` (`.rail-button.active` and `aria-current="page"`).

**Settings window** (`layout/settings/`)

- **`SettingsSection`** — a Settings page's section heading: icon plus title on `.label-xs`, optional one-sentence `description`. *Ext.:* `icon`, `title`, `description`, `children`.
- **`SettingsDescription`** (same file) — the explanatory sentence under a section or a choice row, `text-xs text-muted`. *Ext.:* `children`, `className`.
- **`SettingsStatus`** (same file) — the feedback line for an action: icon plus one sentence. *Ext.:* `tone` (`success` / `error` / `muted` — an outcome that isn't a defect; picks the icon too), `icon`, `children`, `className`.
- **`SettingsCheckboxGrid`** (same file) — a labelled two-column grid of `BlockCheckbox` rows (the export and import dialogs' include/merge lists). A tick outside the grid's concern (e.g. a toned one that widens what the action touches) goes next to it, not inside. *Ext.:* `label`, `children`.
- **`SettingsChoiceButton`** — the Settings choice-button state chain (`.settings-choice-btn*`, values and focus ring for both themes in the stylesheet): size/limit pickers, the Sidebar page's toggles, the import dialog's mode cards, the start page's automatic backup. *Ext.:* `active`, `layout` (`chip` default; `card` leaves padding to the caller).
- **`SettingsChoiceRow`** (same file) — the wrapping flex row such buttons sit in.

**Other**

- **`CreateItemModal`** (`layout/CreateItemModal.tsx`) — what the rail's plus opens: a `SearchField` over groups of `.create-item-tile`s under `.create-item-group` headings — each dashboard in rail order with a tile per live category of its filter (`createEntryIn(dashboard, { categoryId })`; "All entries" and a dashboard without a category rule get one tile without a category), "More categories" (those no filter names, created in "All entries"), and "Collections": `CREATABLE_VIEWS` plus "Dashboard" (`createDashboardAndOpen`). Typing filters by tile or group name (accent-insensitive); Enter in the search takes the first tile left (`.is-default`), the arrow keys move geometrically between the tiles. A `CREATABLE_VIEWS` tile goes through `lib/createItem.ts`, like every view's own "New" button except Tasks' (which stays on `createTask` and names the row in place). Categories, Tags and Images create in their view's own form: `createItem` only navigates there and marks that `ActiveView` (`takeNewForm`), and the view opens its form through `useNewFormRequest`.
- **`useRailDashboards`** (`layout/RailDashboards.tsx`) — the rail's dashboard buttons: "All entries" on its own and the group of the others, each a `RailButton` with `data-dashboard-id`; drag to reorder, right-click for settings, move up/down and delete. Returns `allButton`, `group` and the `menu` to mount.
- **`PickerRows`** (`layout/PickerRows.tsx`) — the vault picker's tiles and the rows that open in their place: `VaultRow` (a vault here as a tile, "only here" under the name), `CreateTile` (the last tile), `EditRow` (name and icon, in the tile), `CreateRow`, `DeleteConfirmRow` (with `InlineConfirm` and a danger `BlockCheckbox` for the files), plus `VaultGlyph` and `VaultLocationRow`.
- **`PickerServerPanel`** (`layout/PickerServerPanel.tsx`) — the start page's Sync section, a placeholder until sync comes back (a `.start-panel` with one sentence, nothing to act on).
- **`PickerStorePanel`** (`layout/PickerStorePanel.tsx`) — the same kind of placeholder for the store, stacked below the Sync section in the left column (`.start-later`); both name v0.3.0.
- **`StartBrand`, `StartLanguage`, `StartSection`, `StartAppearance`, `StartAutoBackup`, `StartUpdateSource`, `StartUpdates`** (`layout/start/`) — the start page's left column on the frame (mark, name, tagline, links, version and author), the language menu at the left of the sheet's foot, the section frame of the sheet (label, icon, actions on the right; no box), its Appearance (theme cards), its Automatic backup (a `start-panel` with a `BlockCheckbox` per vault, the settings dialog's choice rows and `VaultLocationRow`), and the right of its foot (check, install, and the update server popover with the source and the check on start).
- **`VaultLocationRow`** (in `layout/PickerRows.tsx`) — choose-folder button plus the folder a new vault will land in, the path in full on its own wrapping line. The vault picker's create row, the add-vault import (`useVaultImport`) and the automatic backup's folder (`start/StartAutoBackup.tsx`), where the reset goes back to each vault's own `backups/` folder.
- **`EmeraldMark`** — the static brand mark, a round emerald whose cut follows the pentagram: the title bar's logo on Windows and Linux (20px) and the start page's brand (112px, `StartBrand`). At 24px and below a simpler cut takes over. Colours are class names in `src/index.css` (`.emerald-mark*`) on `--mark-accent` and `--mark-line`, so a custom theme tints it (Parchment keeps Noctis's jade); a presentation-attribute `var()` silently falls back to black on engines that don't substitute it (the trap `public/splash.css` avoids too). The shape also lives in the loading screen and the two `src-tauri/icons/source/*.svg` templates, none of which can import this component — changing the cut means updating them by hand. *Ext.:* `size` (required), `className`.

`Button` is the building block most likely to be bypassed. A raw `<button>` is only right when it is not an action button at all: menu entries, list rows, chips, tabs and nav items are structurally something else and have classes of their own. An action button with a hand-written Tailwind chain, by contrast, is always a mistake: it would not get the states and tokens of `Button`.

### `src/components/blocks/` — Content Blocks

See [`architecture.md` → Content Blocks](architecture/blocks.md#content-blocks) for the stored format.

- **`BlockStack`** — an entry's body as a stack of blocks. Hosts the entry's text editors (`useTextEditorHost`: the sticky toolbar, `LinkPickerModal`, chip navigation, file and pointer drops, the drag ghost) and handles the `lib/links.ts` link requests. A dragged block lifts onto an opaque surface until it has settled in its slot. *Ext.:* `initialContent` (initial value only — remount via `key`), `isEditing`, `placeholder`, `onChange(content)`.
- **`BlockFrame`** — a block's shell: invisible in read mode; in edit mode a quiet header (icon, label); grip and "…" menu appear on hover or focus. Keeps its body at one tree position across modes, so a mode switch never remounts a block. *Ext.:* `icon`, `label`, `onGripPointerDown`, `onOpenMenu`, `children`.
- **`blockViews.ts`** — type → component (`BLOCK_VIEWS`). Every view gets `block`, `isEditing`, `onHtmlChange`/`onBlockChange`/`onPersist` (absent while the entry is locked, except for a block that locks it), the entry's `effects` (`EntryEffects` from `entryEffects`: locked, concealed — by block or part ID) and `context` (the entry and its day, `BlockContext`). Imported only by `BlockStack` — the text block pulls in TipTap. *Ext.:* new block types register their component here, their interfaces as a `BlockTypeDef` under `lib/blocks/kinds/` (see [Registry and interfaces](architecture/blocks.md#registry-and-interfaces)).
- **`blockSidebarViews.ts`** — type → `{ Read?, Edit? }` settings a block type brings, looked up by the *resolved* type (a too-new data version gets none); only `Edit` receives `setAttr`. Must not import TipTap (the sidebar is eager). *Ext.:* new types register their settings here.
- **`components/blocks/toolkit.ts`** — the toolkit's component half: `storeBlockPicture(path, tags)` (a file from the disk into the vault and "Images"), `useBlockStorage(block)` (the type's storage tag, made when missing), `useBlockAction(blockId, actionId, handler)` (how a view carries out its type's action). A block view uses these instead of its own.
- **`blockActions.tsx`** — the menu entries stack and block management share: `addBlockActions`, `typeBlockActions` (the type's actions and settings), `commonBlockActions` (duplicate, remove). **`BlockReadActions`** (`BlockSidebarArea.tsx`) — the "Actions" section of the properties panel while reading.
- **`UnknownBlock`** — fallback for a type this version can't render: inner HTML through DOMPurify with a tight allowlist (no `style`/`class`/forms), links opened via `openUrl` only for http(s), read-only.
- **`BlockErrorBoundary`** — wraps every block's view: a block whose render throws falls back to `UnknownBlock` instead of blanking the app (which would repeat on every start, since the open tab is restored). Retries when the block is replaced. *Ext.:* `block`, `children`.
- **`BlockSidebarArea`** — the right sidebar's block manager, fed by `blockSessionStore`: reorderable rows (states via `sidebarRowStateClasses`, reordered through `usePointerReorder`) with eye, rename, "show title in read mode", duplicate, remove; selecting a row jumps to the block and opens the type's settings below it; a jump-to outline in read mode. The same file exports `BlockAddActions`, the "Insert template" (first, where templates apply) and "Add block" buttons at the top of the right sidebar's body, rendered by `RightSidebar` and in the template editor.
- **`blockActions.tsx`** — the context-menu entries stack and sidebar share: `addBlockActions` (presets, then the user's own blocks) and `commonBlockActions` (duplicate — not for unknown types — and remove). *Ext.:* each menu prepends its own entries.
- **`BlockGlyph`** — a block's icon: a lucide icon, or a user-built block's emoji or image in the same box. *Ext.:* `icon` (`GlyphSource`), `size`.
- **`BlockCheckbox`** — the app's one checkbox: label + `.block-checkbox` + optional hint. Drawn entirely from theme variables, not the native checkbox, so it themes in both palettes without an `accent-color` override. *Ext.:* `checked`, `onChange`, `label`, `hint`, `title`, `tone` (`warning` | `danger` — for a tick that widens what an action touches), `disabled`.
- **`OptionsEditor`** — a choice element's options (rename, remove, add; values store the option id), shared by `FieldsSidebarEdit` and the builder. *Ext.:* `options`, `onChange`, `variant="panel"`.

**Fields block**

- **`FieldsBlock`** — the fields block (`core.fields`): read mode a quiet label/value list in the editor font; edit mode `FieldValueEditor`/`FieldSlotEditor` per element. A `text` element renders `TextEditor` directly, with `hostKey` `<blockId>:<elementId>`. Controlled — writes through `onBlockChange`/`onPersist`.
- **`FieldValueEditor`** — the input for a kind whose value lives in the block's data JSON (text/number/date, `Dropdown` for choice and moon phase, `ToggleSwitch` for yes/no, a checklist). Shared with the builder's "Prefill". *Ext.:* `element`, `value`, `onChange`.
- **`FieldSlotEditor`** — the input for a kind whose value lives in the block's markup slot (`LinkEditor` for `link`, an image picker for `image`). Shared with the builder's "Prefill". *Ext.:* `element`, `slot`, `onChange`.
- **`BlockLink`** — `LinkEditor` (chosen entry with ×, else the search) and `LinkTarget` (a live chip that opens the entry), for a link stored as a chip in a block's markup — the link element and the sigil charge's charging technique. *Ext.:* `slot`/`onChange`, `target`/`onRemove`.
- **`FieldsSidebarEdit`** — the fields block's sidebar settings: per-element label, where it shows outside the block (`FieldUseToggles`), choice options, "hide in read mode when empty" (not for kinds `canBeEmpty` excludes); "fully read-only" for the block.
- **`FieldUseToggles`** — a field's three uses outside its block (info line, properties panel, filter and sort) as three icon switches (`TabIconButton`, `aria-pressed`) in one bordered frame, each with a tooltip; a use the kind cannot have stays greyed out in place. Used by the block builder's field rows and `FieldsSidebarEdit`. Unlike `IconToggleGroup` the switches are independent, not a choice. *Ext.:* `element`, `onChange(use, on)` (the caller applies it to the field as it is then, `withFieldUse`).
- **`useFieldFallbackText`** — the localized texts `serializeFields` writes the readable fallback with; one source for block and sidebar.
- **`BlockDefinitionEditor`** — the builder of a user-built block, rendered by `views/BlocksView.tsx`: emoji, name, fields (add by kind, label, reorder, remove), display rules, and a per-field "Prefill" (`FieldValueEditor`/ `FieldSlotEditor`). Edits a draft that only "Done" writes.

**Sigils**

- **`SigilCalc`** — the calculator as a building block: intention, automatic and manual reduction to the letter bank (both always offered), implemented letters; reads and writes a block-shaped value (`lib/blocks/sigilCalc.ts`) and knows nothing of where it sits, so the sigil block and a later calculator block of its own carry it the same way. Read-only while `locked`. *Ext.:* `value`, `isEditing`, `locked`, `onChange`.
- **`DrawingBlock`** — a drawing: the adapter between a block and the [canvas editor](architecture/editors.md#canvas-editor) (fixed in the paint mode of one drawing, with the palette, starting brush and texts it is handed); saves the vector document as block data and its rendered image as a file, 300 ms after the last stroke and once more when editing ends. Used by **`PaintBlock`** (the paint block, canvas swatches) and **`SigilBlock`** (the sigil's drawing part, with the sigil palette).
- **`SigilBlock`** — the sigil block (`core.sigil`): the parts its settings switch on (calculator, drawing, charge), each under a heading of its own; a part concealed by the entry's effects shows `SigilConcealed`, a locked one is read-only. Merges the writes of its parts so that two before the next render build on each other. *Ext.:* the standard block-view props; new parts are added in `SIGIL_PARTS` and the view's `body`.
- **`SigilCharge`** — a sigil's charge: reveal date (optional — without one, loading hides calculator and drawing until unload), charging technique (`BlockLink`), lock scope (whole entry or only this sigil); in read mode load (optional timer) and unload, each with an inline confirmation. *Ext.:* `value`, `isEditing`, `onChange`, `onPersist`.
- **`SigilConcealed`** — the quiet "hidden until …" line. *Ext.:* `revealDate`.

**Canvas**

- **`CanvasBlock`** — the Canvas and Altar blocks: the adapter between the block and the [canvas editor](architecture/editors.md#canvas-blocks) (`fullProfile` less the parts switched off), with `ImageStrip` below when "Images" is on, disk drops through `useFileDrop`, the render on Done and the export dialog. *Ext.:* the parts (`CanvasParts`) and the strip's tag in the block's config.

The text editor `BlockStack` hosts lives in `src/components/editors/text/` (see [`architecture/editors.md`](architecture/editors.md#text-editor)). Image inserts report failures through `ImageNoticeModal` (above).

### `src/components/sidebar/fields/` — Property Panel Building Blocks

**Read and edit sections**

- **`SidebarSection`** — a collapsible section of the right sidebar, in read and edit mode alike (Properties, Linked entries, Tags, Blocks, a block page's Display). Read and edit share each section's `storageKey`, so a section closed while reading stays closed while editing; open/closed is `usePersistedFlag(storageKey)`. The header sits `pl-1 pr-1.5` inside the edge; rows' icons start at the middle of the heading's chevron (`pl-[9px]`), and the content's `mr-0.5` plus the rows' `pr-3` end values where the heading's count begins — a commented exception to the padding rule below. *Ext.:* `storageKey`, `label`, `count`. Also exports:
  - `SidebarPropertyRow` — icon, label, value (`muted` for "None"/"Off"; the label truncates first, the value is capped at 65%).
  - `SidebarItemRow` — a clickable row (icon, label, right-aligned `meta`); `active` marks the selected one; `action` appends a button (e.g. `SidebarRowRemove`, the 24px "×"); `gone` strikes the label through (`.link-gone-label`) and sets the "deleted or in the trash" tooltip.
  - `RowIcon` (the fixed 16px icon column), `SidebarEmpty` (a section's empty line).
- **`SidebarSectionHeader`** — the collapsible heading itself: chevron plus small uppercase label on `.sidebar-section-title`, optional count. Controlled, because callers may keep open state differently (`SidebarSection`, the block management). *Ext.:* `label`, `open`, `onToggle`, `count`, `className` (spacing only).
- **`EntryReadSections`** — the entry's read-mode sidebar body (`EntryPropertiesPanel`): `PropertiesSection` (omitted when no `properties` are passed), `LinkedEntriesSection`, `TagsSection`. Also exports `CategoryPropertyRow` (a trashed category shows "None", not its raw id). *Ext.:* `properties`, `content`, `tags`.
- **`LinkedEntriesSection`** / **`LinkedEntriesField`** (`LinkedEntriesField.tsx`) — the "Linked entries" section, read and edit, sharing `useLinkedEntries`. Rows are sorted by `categoryLabel`, category right-aligned; links to a gone target (`resolveLink`) follow last, struck through, marked "Deleted". Links are read out of the entry's own `content` (`extractInternalLinks`, see [Internal Links](architecture/editing.md#internal-links)), not an id array. In read mode a click reveals the link in the text, or opens the target when the text doesn't hold it. In edit mode each row gets a remove "×" and below sits the inset "Link entry …" search; adding appends a link block into the editor and removing asks the editor to delete it — both via the `lib/links.ts` event protocol, since the field has no reference to the TipTap instance. Suggestions are sorted by `updatedAt`, newest first. *Ext.:* `content`.
- **`TagsSection`** / **`TagsField`** (`TagsField.tsx`) — the "Tags" section: read mode a read-only `TagInput` (`chipSize="row"`) or `SidebarEmpty`; edit mode an editable `TagInput` with 24px chips, a round "×" and the inset "Add tag …" field, whose suggestions create tags inline or point at the Tags dashboard. The tags the entry's blocks give follow the user's in both modes, with a dashed edge and the block's mark instead of the "×" (`TagInput`'s `blockTags`). *Ext.:* `tags`, `onChange`, `blockTags`.
- **`TagInput` drafts** (`ui/TagInput.tsx`) — dialogs that save later (dashboard settings, "Add images", "Edit image") pass `drafts`/`onDraftsChange`: a new name becomes a draft with a generated id inside `tags` (chips stay in tag order) and no tag exists until the dialog calls `commitDraftTags(tags, drafts)` on Save, which returns the list with real ids. Cancel drops the drafts. Without these props `TagInput` creates the tag at once, as the sidebar does. A new dialog with a tag field uses the drafts too — unless the field is a filter (the export menu): that passes `existingOnly` and offers only existing tags.

**Edit-mode controls**

- **`EditProperties`** (`EditProperties.tsx`) — the edit-mode counterpart of `SidebarPropertyRow`: the same row with a control as its value.
  - `EditPropertyRow` — 36px, the label never truncates. *Ext.:* `icon`, `label`.
  - `PropertySelect` — a value button with chevron (`.prop-value-btn`, max 130px), its `Dropdown` portalled and right-aligned. *Ext.:* `value`/`options`/`onChange`, `text`, `muted`, `ariaLabel`.
  - `MediaPropertyRow` — icon or cover image: the button shows a thumbnail, the emoji or "+ Add"; a click opens Choose image / Emoji / Remove, an empty cover goes straight to the file dialog; icons go through `readIconFile` (`lib/imageLimits.ts`) and then `IconCropDialog`. *Ext.:* `rowIcon`, `label`, `kind` (`icon`/`cover`), `value`, `onChange`, `onRemove` or `fallback` (templates and blocks: "Remove" resets to the default icon), `suggested` (what a block suggests: shown with `FromBlockMark` while the user set nothing; a `fixed` one stands without a menu).
  - `EditSidebarBody` — a library page's sidebar body.
- **`CategoryIconCoverRows`** — Category, Icon and Cover image as edit-mode rows of every entry; a category change saves at once. Icon and cover show what a block suggests (`MediaPropertyRow`'s `suggested`). *Ext.:* `entry`, `update`, `blocks`.
- **`BlockSourced.tsx`** — what an entry's blocks put into its panel: `useEntryBlockSources(entry)` (`suggestions`, `blockName`, `blockTags`), `BlockPropertyRows` (the blocks' rows as `SidebarPropertyRow`s, each with `FromBlockMark`). The mark itself is `ui/FromBlockMark.tsx` (the rail's "Blocks" icon, the block named in the tooltip — `fromBlockTitle`, also the tooltip of a read-mode action; *Ext.:* `name`, `fixed`, `className`).
- **`LinkedEntryPicker`** — the chrome behind `LinkedEntriesField` and `BlockLink`: search input, result menu portalled `fixed`/`z-9999` to `document.body` (an absolute menu would be clipped by the sidebar's `overflow-y-auto`), outside-click, empty state, flip-up. Keyboard: the arrows move the current row (`.linked-entry-menu-item--current`), wrapping at the ends, and so does the pointer; Enter picks it. A new query resets it to the top, a store change does not. Also exports `LinkedEntryChip` (`gone` strikes it through with the tooltip) and `LinkItemIcon` (a link target's icon: image, emoji or the type's default). *Ext.:* `results`/`resultKey`/`renderResult`, `fieldIcon` (renders the input inside `.sidebar-add-field`).
- **`AltarIcon`** (`lib/altarIcon.ts`) — a candle on a table, since lucide has none; the icon of the Altar block (`lib/blocks/blockTypes.ts`, `lib/blocks/presets.ts`).
- **`Favicon`** — emoji-or-image picker including upload (through `IconCropDialog`), as a row of buttons. A bare fragment — callers supply heading, wrapper and "None" fallback (the dashboard settings). Also exports `FaviconGlyph`, just the glyph (default 20px; `className` overrides).
- **`IconCropDialog`** (`sidebar/fields/IconCropDialog.tsx`) — cutting a chosen picture to an icon before it is taken: a `Modal` with the picture behind a square frame shaped like the icon (outside dimmed by `--modal-scrim`), drag or arrow keys to move, `RangeField` and scroll wheel to zoom (the wheel towards the pointer), 1× to 8×; the picture always covers the frame. Apply hands on a square PNG data URL of at most `ICON_MAX_EDGE` (128px, never larger than the cut-out's own pixels), which goes on through `useShrunkIcon` like any icon; an animated GIF becomes its first frame. Cancel, Escape and the backdrop leave the icon as it was. The two icon pickers, `MediaPropertyRow` and `Favicon`, open it — so every image icon (entries, templates, blocks, languages, dashboards) is cut here. Focus starts on the picture, so Enter applies; callers key it by `src`, so another picture starts from scratch; a picture that does not decode cancels and calls `onUnreadable`. *Ext.:* `src` (the picture as a data URL), `onApply`, `onCancel`, `onUnreadable?`.
- **`DashboardGlyph`** (`ui/DashboardGlyph.tsx`) — a dashboard's glyph: its own icon through `FaviconGlyph`, else the built-in's or the default dashboard icon (`dashboardIcon`). One renderer for the rail, the plus's tiles, the sidebar setting, the import destination and the category dialog. *Ext.:* `size` (14, 16 or 18).

**Horizontal padding has exactly one source in the right sidebar** — `SidebarColumn`'s scrolling body. No panel and no field here adds a `px-*` of its own (the read view's footnote carries a cosmetic `px-1`, which is alignment, not padding); see [`design.md`](design.md#heights-and-spacing). `SidebarSection`'s `mr-0.5` and its rows' `pl-[9px]`/`pr-3` are the one deliberate exception, commented in place: they line the rows' icons up with the heading's chevron and their values up with the heading's count.

### `src/hooks/` and `src/lib/` — Shared Logic

**Hooks**

- **`useEntryEditor`** — the editor lifecycle: debounced auto-save, save-on-navigate, save-on-unmount and Cancel (`restoreOnCancel`, which answers `EDIT_ENDED` when the page no longer shows the entry — it moved the entry back to its module, or the tab changed meanwhile), parameterised over `buildPatch()`/`update()`. The baselines it restores from live in `store/entryEdit.ts`.
- **`useEditActions`** — registers a view's Save/Cancel/Delete into the right sidebar's action bar while `active`, ref-latched so the sidebar never calls a stale closure.
- **`store/entryActions.ts`** — `deleteEntryWithUndo(id)` (an entry into the Trash with Undo; a page showing it goes back to the dashboard it was opened from — the entry page writes its pending edits first) and `deleteTaskWithUndo(id)`: the one delete of every list, the entry page and the Tasks view.
- **`useLibraryItemRemove`** — moving an item of a library view to the Trash with undo, and back to the list if its page is still open. Blocks, Templates, Lexicon. *Ext.:* `viewType`, `remove`, `restore`, `clearDraft?`, `undoKey`, `logTag`.
- **`useDraftPage`** — the draft lifecycle of a `LibraryPageFrame` page: opens from a `DraftStore<T>` entry or the saved row, mirrors every change back (so edits survive `MainArea` unmounting the view), and on "Done" saves only the fields changed since opening. "Cancel" discards the draft, or, for a page just created (`onCancelNew`), deletes it into the Trash with Undo; the leave guard's "Discard" runs the same. *Ext.:* `store`, `id`, `saved`, `save(id, patch, base)`, `onClose`, `onCancelNew?`, `logTag`.
- **`useShrunkIcon`** — stores an image icon (a data URL from the picker) as a 128px file in the vault's `icons/` (`saveIcon`, `lib/icons.ts`) before its name lands in a draft or record, passing an emoji straight through; the last call to resolve wins, so "Remove" (`''` or the default icon) goes through it too. Its promise settles after the write `apply` returns, so Cancel can wait for it. Every icon field goes through it: blocks, templates, languages and entries. *Ext.:* `apply`, `logTag`.
- **`lib/export.ts` → `exportArticle`** — one entry as an `<article>` of a PDF or HTML document (top bar, title, tags, sanitised content, link chips, pictures at the item's level). *Ext.:* `opts.bundleIds` (links into the same file become anchors), `opts.footerHtml` (the HTML references). `exportDate` is the exports' one date format.
- **`lib/exportFonts.ts`** — the fonts of PDF and HTML: `EXPORT_FONT_OPTIONS` (the app's `FONT_OPTIONS` plus common system fonts), `fontStack`, `embeddedFontCss` (an app font's faces from `fonts.css` as data URLs), `typographyCss`.
- **`lib/icons.ts`** — `iconSrc` (the URL of an icon file; every `<img>` of an icon uses it), `saveIcon`, `portableIcon` (a data URL for documents outside the app: PDF, HTML, Markdown), `plausibleEmoji` (an icon value from a file kept only if it can be an emoji), `findUnusedIcons`.
- **`useSaveAsTemplateAction`** — the "Save as template" context-menu entry for every entry with a block stack. *Ext.:* `id`.
- **`useOpenInNewTabAction`** — the "Open in New Tab" `ContextMenuAction` for an `ActiveView`; the menu counterpart to `DashboardItem`'s middle-click.
- **`useNewFormRequest`** — runs a collection view's own "New" (`openNew`) when the rail's plus opened the view to create something there (`takeNewForm` in `lib/createItem.ts`, one-shot on the `ActiveView` object), also when the view was open already. Used by Categories, Tags and Images.
- **`useDeepLink`** — the global search's deep link for a view without a detail page: `{ type, id }` runs the caller's `onOpen(target)` once (clear search/filters, expand groups, open the picture), then scrolls the row carrying `rowAttribute` into view. Latches on the `activeView` object (fresh per navigation) in a module-level `WeakSet`, so `items` can be a dependency and a remount, tab switch or history step does not replay it over the user's filters. Returns `scrollTo(id)`. Used by Tasks, Categories, Tags and Images.
- **`useOutsideClick`** — the mousedown-outside(-plus-Escape) dismiss pattern. *Ext.:* `refs` (plural — a portalled popover is no DOM descendant of its trigger), `escape` (`true`, or `'capture'` to beat a surrounding `Modal`'s handler), `capture` (where Tauri's `drag.js` stops propagation on a drag region before bubble listeners see the click), `delay` (skip the opening mousedown itself).
- **`useEmojiSearchData`** — the emoji search dataset for `EmojiPicker`: `null` until loaded, not fetched while `enabled` is false. Wraps `lib/emojiSearch.ts`.
- **`useLinkItems`** — the store-subscribed half of `buildLinkItems`: every linkable entry and task in one memoised list, shared by every caller while the store inputs are unchanged (`[[` suggestions, `LinkPickerModal`, `LinkedEntriesField`); `useLinkTarget` resolves one link through it (`resolveLink` in `lib/linkItems.ts`): the live item, or a stand-in with the chip's stored title and `gone: true` — the source of a chip's icon, label and gone state.
- **`useGlobalSearch`** — assembles the search corpus from the stores and runs the query; backs `SearchModal`.
- **`usePointerReorder(items, onDrop)`** — drag-to-reorder by grip without animation: pointer events on `document`, no HTML5 drag. Returns `listRef` (each direct child is one row wrapper, measured at its first child), `visualItems`, `draggingId`, `startDrag(e, id)`; `onDrop(ordered)` fires only when the order changed. Used by the block manager, the emoji defaults (`EmojiDefaultsSection`) and `CategoriesView`.
- **`usePersistedFlag(key, fallback?)`** — an on/off preference that survives a restart, per vault (`uiStore.flags`, saved via `store/vaultPrefs.ts`), returned as `[value, toggle, set]`; `set` lets a caller open a section itself (the block manager does so for a just-added block). A vault without the key falls back to the app-wide `localStorage` value under the same key, then to `fallback`. For preferences, not working state.
- **`useSessionState(key, initial)`** — `useState` for working state that should outlive a module switch but not the session (search, filters, the Trash selection; `store/sessionStore.ts`). Keys look like `tasks.search`; `closeAllTabs` clears them.
- **`useVaultPictures()`** — every picture of "Images" as `PictureItem`s (file plus its row, or `null`): the rows, and every other stored file a text, a field, a canvas or a block default shows (`isShownUse` in `lib/imageUsage.ts`), none in the trash; reads the folder and the places of use again on mount. Its `loaded` waits for the places of use too (`usesLoaded` in `imageStore`): before them, an unnamed file cannot be told shown from left over, so the views show no empty text meanwhile. `searchPictures` filters by name and note. The one source for the view, the picker and the strip.
- **`useFileDrop(enabled, onDrop)`** — files dragged in from the disk anywhere over the window (Tauri's event; the WebView has no HTML5 file drop): `dragOver`, and `onDrop(paths, point)` with the point in CSS pixels (`dropPositionToCss`). A place that takes drops itself carries `data-file-drop`, and `dropClaimedAt(point)` tells the text editors to leave them alone. Which of the dropped files are images is `acceptedImagePaths` (`lib/storeImage.ts`).
- **`useHorizontalWheel(ref, deps?)`** — a plain (vertical) wheel over an overflowing row scrolls it sideways instead of the page; a sideways trackpad gesture is left alone. A non-passive listener of its own, since React's wheel listener cannot stop the page. The tab bar and `ImageStrip`. *Ext.:* `deps` (re-attach when the row is rendered only later or replaced).
- **`useCollapsedSet(scope, { defaultCollapsed? })`** — collapse state for a group list: `isCollapsed(id)`, `toggle(id)`, `expand(...ids)` (for deep links). `defaultCollapsed` starts every group closed (Tags); the stored set then holds the opened ids. Lives in `uiStore.collapsedGroups` per `scope`, not in view state, because `MainArea` unmounts views on a module switch; remembered per vault. Scopes: the category groups of each dashboard (`dashboard:<id>`), Tasks and Tags.

**Module registry and wiring**

- **`lib/modules.ts`** — the view registry: `CONTENT_MODULE_IDS` (`entries`, `tasks`), `ViewId`, `LeftListTabId` (`all`, `tasks` or a dashboard id), `TASKS_VIEW`, `AUX_VIEWS`, `COLLECTION_IDS`, `CREATABLE_VIEWS`, `ENTRY_ICON`, `ALL_ENTRIES_ICON`/`DEFAULT_DASHBOARD_ICON`, `dashboardIcon`, `TRASH_KINDS`/`TRASH_KIND_ICONS`, `isViewId`. **`lib/entryIcon.ts`** — `entryIcon(entry, category, showMoonPhase)`, the one icon rule for an entry (own icon, else moon phase, else category emoji, else `DEFAULT_ENTRY_ICON`), and `DEFAULT_TASK_ICON`. **Import rule:** lucide-react and types only — no stores, no components. `store/moduleWiring.ts` wires the stores and `components/layout/moduleViews.ts` the lazy views, keeping this file cycle-free and out of bundles that don't need a view chunk.
- **`store/moduleWiring.ts`** — the store half of the registry: `moduleWiring` (each module's reload), `trashWiring` (restore/permanently-delete per `TrashKind`), and `reloadAllStores`/`reloadModules` (the startup/vault-switch/import reload sequence: tags, categories, block definitions, templates and the lexicon, then content). **Import rule:** content stores only, never `uiStore`/`vaultStore`/`trashStore`.

**Content stores**

- **`store/entryStore.ts`** — the one store of all entries (`entries: Entry[]`, no type) with `fetchEntries`/`ensureEntryContent`/`createEntry({ categoryId, blank, createdAt })`/`updateEntry`/ `duplicateEntry`/`deleteEntry`/`restoreEntry`/`permanentlyDeleteEntry`/`getEntry`, the two-stage loading state `pendingContent`, and `findEntry` — see [Entry Store](architecture/modules.md#entry-store).
- **Dashboards** — the one rule for what a dashboard shows and where an entry opens: `lib/dashboards.ts` (`matchesFilter`/`dashboardEntries`, `parseDashboardDisplay`, `sortModeOf`/`sortFromMode`, `dashboardLabel` — the one display-name rule), `store/dashboardStore.ts` (`dashboardById`, `dashboardOrAll`), `store/dashboardActions.ts` (`createDashboardAndOpen`, `deleteDashboardWithUndo`), `store/entryViews.ts` (`entryView`, `viewOfLinkTarget`, the cached `entriesOfDashboard`) and the hooks `useDashboardEntries(id)`, plus `useDashboardPrefs(dashboard, dateField)` — a dashboard's view, sort and grouping as `ListPrefs`, read from and written to its row — see [Dashboards](architecture/modules.md#dashboards). Code that lists a dashboard's entries goes through them, never through a category check of its own.
- **`store/templateStore.ts`** — the templates' data — see [Templates](architecture/templates.md#templates). `startOfNewEntry` (what a new entry begins with) and `useTemplateNoticeStore` (the one "template applied" notice) live here, since the content stores that call them may not import a component.
- **`store/blockDefinitionStore.ts`** — the user-built blocks (`block_definitions`): create, update, soft-delete/restore/purge. Touches no entry; the `.emerald` and backup imports add definitions through `insertBlockDefinitions` (`lib/dbBackup.ts`).
- **`store/blockSessionStore.ts`** — the bridge from the open entry's `BlockStack` to the block manager: current block structure plus a stable `BlockStackApi`, and the manager's selected row (`select`, `useSelectedBlockId(sessionId)`; `revealInSidebar` asks the sidebar to open its section for a just-added block). In memory only; `clear(api)` only removes the caller's own session and its selection.
- **`store/draftStore.ts`** — `createDraftStore<T>()`, the unsaved-drafts-by-id store behind a `LibraryPageFrame` page (`useBlockDraftStore`, `useTemplateDraftStore`, `useLanguageDraftStore`), written into the vault's `drafts.json` (`restoreDrafts`, `flushDrafts`, `detachDrafts`); `clearAllDrafts()` on a replace-mode restore.
- **`CategoryEditModal`** (`categories/CategoryEditModal.tsx`) — creating and editing a category: emoji and name (locked for a built-in), the start template as a list of `FilterRow`s ("Default template (name)" first), and where it shows up — the dashboards whose filter names it, and those without a category filter. Read-only there: the dashboards' filters are set in their settings. *Ext.:* `category` (none: a new one), `onClose`, `onDelete`, `onCreated` (a new one was saved).
- **`SymbolEditModal`** (`symbols/SymbolEditModal.tsx`) — one of the vault's own symbols, large, to rename or delete. *Ext.:* `symbol`, `onClose`, `onDelete`. `SymbolGlyph` (`editors/canvas/symbols/SymbolPicker.tsx`) draws a symbol; with `fit` it fills its square instead of its 100 × 100 box.
- **`store/vaultPrefs.ts`** — per-vault preferences: loads `uiStore`'s preference fields when a vault opens (`loadVaultPrefs`), writes changes to `localStorage` under `vault-prefs:<vaultId>`, drops them with the vault (`forgetVaultPrefs`) — see [Tabs and Workspace State](architecture/navigation.md#tabs-and-workspace-state).
- **`store/settingsStore.ts`** — the open vault's settings: `loadForVault(vaultId)` (runs after the unlock gate has checked the database and before the first `getDb()`, whose trash purge needs the retention period; it awaits `deviceStore.adoptFromVault`), `clear()`, `replaceSettings(settings)` (backup import), `update(group, patch)`. Fonts, interface size and editor text size apply immediately and are mirrored into the `localStorage` keys `main.tsx` reads before a vault is open; writes to `settings.json` are serialized through `lib/serialize.ts`.
- **`store/deviceStore.ts`** — the installation's language and theme, custom themes included (`device.json`, see [Device Settings](architecture/storage.md#device-settings)): `load()` at start, `setLanguage`, `setTheme`, `addCustomTheme`, `removeCustomTheme`, `adoptCustomThemes` (a backup's), `adoptFromVault` (a vault's from before). Applies immediately, keeps the boot mirror, writes serialized; an unreadable file is set aside and nothing is written until the user chooses.
- **`store/autoBackupStore.ts`** — the automatic backup's setting and, per vault, its folder, newest backup, running flag and last failure; written only by `lib/autoBackup.ts`, read by `StartAutoBackup` and the rail's start page button (its dot). See [Automatic Backup](architecture/storage.md#automatic-backup).
- **`store/imageStore.ts`** — the rows of "Images", the folder's files and the places of use. **`takeIn(file, { name, tags })`** is the one rule for taking a file into "Images" (the add dialog, the picker, a drop on a canvas): a new row under `name`, or the row already there for that file keeps its name and gains the tags, and comes back from the trash with its `detached` emptied — taken in anew, not restored into its texts, or the cleanup would keep the files of those snapshots. **`discardRenders(files, keep)`** removes the pictures a drawing or a canvas rendered for itself while editing, a moment after editing ends, unless the saved entry, `keep()` or anything else still shows them (`removeUnusedFiles`).
- **`store/imageNoticeStore.ts`** — the store behind `ImageNoticeModal`; `reportImageError(err, context)` shows the size notice for an `ImageTooLargeError` and otherwise logs, so a call site needs no try/catch branching.

**Links**

- **`lib/pointerDrag.ts`** — `trackPointerDrag(start, { threshold, onStart, onMove, onEnd })`: a press followed on the document until release or `pointercancel`, with the travel (`DRAG_THRESHOLD_PX`) that turns a press into a drag. A plain function, so ProseMirror node views and canvases can call it from `pointerdown`.
- **`lib/linkItems.ts`** — `buildLinkItems(sources, t)`: the one source of a link target's icon, label and category for entries and tasks (`SuggestionItem[]`); `linkItemKey`/ `linkItemsByKey` (the `targetKind:id` key, cached per list); `resolveLink` (`ResolvedLink`): a link's live item, or for a target in the trash or deleted a stand-in with the chip's stored title and `gone: true`. `emeraldFormat.ts` calls it directly with a `getState()` snapshot — `LinkItemSources` is the extension point that makes that possible.
- **`lib/internalLinkHtml.ts`** — reading and writing an internal link chip's stored HTML, deliberately DOM-optional: `extractInternalLinks` (id, target kind and the decoded stored label — a scan of the span start tags through `htmlTags` that runs on the database path and in the schema-check Node harness, where there is no browser), `isValidLinkTarget` and `decodeHtmlAttr` (attribute entities, also used by the block format); `rewriteInternalLinkIds` (start-tag based, the backup merge); `remapInternalLinks`/`internalLinkChipHtml`/`internalLinkBlockHtml` need a real DOM (`.emerald` import/export, the editor). `internalLinkBlockHtml` is the one definition of an appended link block (divider, category heading, chip).

A request resolves to `true` only if an editable, listening editor accepted it (`preventDefault`); the field falls back accordingly.

**Blocks and templates**

- **`lib/blocks/`** — the pure half of the content-block registry. **Import rule:** types, `lucide-react` and pure `lib` only.
  - `types.ts` (`BlockInstance`, `TEXT_BLOCK_TYPE`), `blockType.ts` (`BlockTypeDef`: the interfaces a type brings), `kinds/` (one file per built-in type), `blockTypes.ts` (the registry: `registerBlockType`, `resolveBlockType` — `undefined` for an unknown type or too-new data version — and the one place that asks a block: search text, storage, actions, copies, upgrades), `toolkit.ts` (`RefReporter`, `blockContext`, settings, data version), `entryProperties.ts` (what the blocks suggest for the properties, by user, block, category).
  - `blockHtml.ts` — `parseBlocks`/`serializeBlocks`/`createTextBlock`, `DOMParser`-free, tested by `npm run check:blocks`.
  - `blockAttrs.ts` — instance-attribute and naming rules for stack, sidebar and export (`isBlockHidden`, `customBlockTitle`, `showsTitleInRead`, `withBlockAttr`, `blockLabel`/`blockTypeLabel`/`elementLabel`, …).
  - `exportRender.ts` — `renderBlocksForExport(content, format, text)`: asks each block's `export` for its parts in the format and lays them out; knows no block type. Covered content is the `.export-concealed` box (cover, switch, body), switched by the HTML file's script.
  - `fields.ts` — the fields block (`parseFields`/`serializeFields`/`createFieldsBlock`, `isElementEmpty`/`isHiddenInRead`, `linkFromSlot`/`imageFromSlot`).
  - `presets.ts` — `BLOCK_PRESETS` (what "add block" offers), `createFromPreset` (including `def:<id>`), `ELEMENT_KIND_ICONS`, `blockIcon`.
  - `definitions.ts` — user-built blocks (`instantiateDefinition`).
  - `entrySummary.ts` — `entryBlockSummary`: per entry what the blocks do to it (`effects`: lock, concealed), the info line in both forms (`listInfo.ts`), the blocks' suggestions and panel rows (`entryProperties.ts`) and their values to filter and sort by (`entryBlockValues`), cached per content and day.
  - `blockRows.ts` (`toBlockRow`/`fromBlockRow`: a block as a row of `blocks` and back, losslessly), `plainText.ts` (`htmlPlainText`: markup as text without a DOM), `blockRefs.ts` (`blockRefs`: what a block points at, the rows of `block_refs` — asked of each type; `blockTagsOf`, `linkedIdsOf`, `blockWithoutImage`), `position.ts` (`keyBetween`/`positionsFor`: string keys that sort, so a move writes one row), `blockRemap.ts` (`remapBlock`: a block brought along by an import, pointed at the pictures and entry IDs of this vault), `blockQuery.ts` (`entriesWithFieldValue`: asking the rows for a field's value with SQLite's JSON functions). The way blocks are stored is in [Blocks](architecture/blocks.md).
  - `canvas.ts` (the Canvas and Altar blocks: `parseCanvasBlock`, `withCanvasScene`, `withCanvasStripTag`, `storedCanvasElement`/`storedImageElement`, the one stored form of an element), `paint.ts` (the Painting block: `parseDrawing`/`withDrawing`), `sigil.ts` (the sigil block: parts as blocks of their own, the charge, its effect), `sigilCalc.ts` (the calculator's value), `blockJson.ts` (reading and writing a block's data JSON), `templates.ts` (a template's shape and how an entry finds its start template — see [Templates](architecture/templates.md#templates)).
- **`lib/blockStore.ts`** — the one reader and writer of the block rows of entries and templates: `loadBlocks` (rows to blocks, remembered as saved), `contentOf`/`readContent`/`readContents` (the block HTML the stores carry), `planBlockWrite`/`planContentWrite` (statements for only the blocks that changed, against what was saved before), `replaceOwnerBlocks` (a whole stack from a seed), `copyBlockStatements`. A store never writes `blocks` or `block_refs` with its own SQL. A write that overlaps another of the same owner is not remembered as saved, so the next save writes the full difference.
- **`lib/htmlTags.ts`** — `htmlTags(html)`: the tags and comments of markup in one linear, quote-aware pass, without a DOM. Every reader of markup that must run on imports, on the database path or in Node (`parseBlocks`, `htmlPlainText`, `extractInternalLinks`, link rewriting, `isBlankContent`) goes through it; a regular expression over such markup can backtrack for minutes on crafted input.
- **`storedImageNamesIn(text)`** (`lib/schema.ts`) — every stored picture name anywhere in a text, markup or JSON; with `blockRefs`, the way an entry's pictures are collected.
- **`lib/templateTags.ts`** — `withUsableTags(template)`: the template with only the tag ids it may hand to a new entry — only live tags; a template never creates a tag. `registerTagLookup` lets `tagStore` supply the is-live check without this module importing it back (that import would cycle).

**Categories, titles, dates, sorting, grouping**

- **`lib/categories.ts`** — `categoryLabel(t, cat, fallback)`: the one builtin-vs-custom display-name rule (a builtin via `categories.builtin.<id>`, else its stored name). `categoriesUsedBy(all, items)`: the categories a view renders — everything an item points at; a just-created category reaches a module only once an entry points at it. `categoryUsageCounts`: entries and tasks per category (`CategoriesView`'s columns). `hasUncategorized(all, items)`: whether any item's category no longer resolves (moved to Trash). `lookupCategory`: a category by id from a map or record. `categoryKey(name)`: the one comparison of category names (trimmed, case-insensitive), for the store and the imports.
- **`lib/entryTitle.ts`** — the one title rule: new entries are stored with an empty title, and `displayTitle(t, 'entry' | 'task', title)` is what every list, card, tab, search result, chip, drag label and export shows (the title, or the translated "Untitled …"). `hasOwnTitle(title)` tests for an own title (never compare against the English default) — see [`database.md`](database.md#key-conventions).
- **`lib/blockValueText.ts`** — `blockValueText(t, value, form)`: a value a block delivers, worded for the info line and the panel (a date long or short, a number in the app's language, yes/no).
- **`lib/formatDate.ts`** — `formatEntryDate`/`formatIsoDateLong`/`formatIsoDate`/`formatIsoDateShort` (an ISO day in the long, list or short left-list form, read as a local date)/`formatMonthGroup`/`formatTimeDistance`/`formatWeekday`/`weekdaysInLocaleOrder`: the only source of locale-aware date formatting, wired into `changeAppLanguage` (date-fns locales lazy-load per language). `lib/export.ts`, `lib/htmlExport.ts` and `lib/emeraldFormat.ts` deliberately don't use it — file exports stay locale-independent (`exportDate`).
- **`lib/sortItems.ts`** — the one `SortMode` comparator for every dashboard: date/title getters plus an optional tiebreak. Grouping is a separate axis (`GroupingMode`). `title` is required only when the item type has no `title` field (`TitleOption<T>`, for an item sorted by `name`, say). An optional `count` getter backs `count_desc`; `manual` keeps the items' own order (the categories' `sort_order`).
- **`lib/groupBy.ts`** — `groupBy(items, keyFn)`, `groupByMonth` (via `formatMonthGroup`), `groupByCategory(...)` — one group per category plus a trailing `UNCATEGORIZED_KEY` group, only when there are orphans. `countBy`/`countByCategory` (same orphan rule) feed the sidebar's `FilterList` counts.
- **`lib/viewMode.ts`** — `isCardView(view)` (`cards` or `cards_wide`) and `isWideCardView(view)`. Views branch on `isCardView`, never `view === 'cards'`, so `cards_wide` lands in the same branch everywhere.

**Infrastructure**

- **`lib/serialize.ts`** — `serialized(serialKey(domain, id), task)` chains same-key async tasks, so a store's read-merge-write update never runs against a stale snapshot. `drainSerialized()` awaits every queued chain (vault switch, replace/add-vault import, each automatic backup run). See [Store Write Serialization](architecture.md#store-write-serialization).
- **`lib/reveal.ts`** — `scrollIntoViewCentered(el)` (reduced-motion aware) and `flashReveal(el, className, ms)`: the "here it is" scroll-and-flash of the link chip and the block stack's jump-to, also for a block just added or duplicated.
- **`lib/motion.ts`** — `REORDER_SPRING`, the one spring for framer-motion `Reorder` lists (tab bar, block stack, the builder's field list). The block manager reorders without animation via `usePointerReorder`.
- **`lib/dragChannel.ts`** — `createDragChannel<T>()`, the set/get/subscribe pub-sub behind `dragState`/`imageDragState` and the text editor's image drag.
- **`lib/styleClasses.ts`** — repeated Tailwind chains. **The established home for them** — extend it rather than bypassing it.
- **`lib/platform.ts`** — `isMacOS`, `isWindows`, `platformName`, `isTauri`, `usesCustomWindowControls`. The **only** permitted source of platform detection; everything else branches through `html[data-platform]` in CSS, never through scattered `navigator.userAgent` checks.
- **`lib/tabs.ts`** — tab ids, per-tab navigation history, `isContentView`.
- **`lib/helpers.ts`** — `generateId`, `nowIso`, `localIsoDay` (a local `YYYY-MM-DD`, also the "today" sigils compare their dates with), `isRecord`/`asRecord`/`asString` (reading parsed JSON), `exportFilename` (every export's default file name), `listOf(items, language)` (a language-correct "A, B and C"), `isImageIcon`, `iconTitle`, `isValidHexColor`, `formatBytes`, `ACCEPTED_IMAGE_MIME`, `isAcceptedImageFile`, `readFileAsDataUrl` (any Blob, not only a file), `oneOf(raw, options, fallback)` (for values read back from a file or `localStorage` that must land on one of a fixed set).
- **`lib/vaultSettings.ts`** — the vault-settings model: `VaultSettings` and its groups (`SETTINGS_GROUPS`), `DEFAULT_VAULT_SETTINGS`, `normalizeVaultSettings` (field by field, unknown keys left standing so a newer build gets them back after a detour through an older one), `importableSettings` (the same but *dropping* unknown keys — a backup file is untrusted input), `withSettingsGroups` (a Merge import's per-group pick), `readVaultSettings`/`writeVaultSettings`, and the one-time app-wide-to-per-vault migration (`captureLegacySettings`, `initialSettingsFor`, `readAppearanceMirror`).
- **`lib/storeImage.ts`** — a file into the vault's `images/`: `storeImageFromPath` (a disk drop: prepared by the vault's limits when that could change it, else copied as it is), `storeImageFile` (a chosen or pasted `Blob`), `fileBaseName` (a new picture's first name). Every way in from the disk goes through it. `acceptedImagePaths(paths)` (by extension) and `acceptedImageFiles(files)` (by type, `isAcceptedImageFile`) keep the images among dropped or chosen files and show the format notice (`ImageNoticeModal`) when others were left out — every drop and every file dialog filters through them. Pasting picks the images out of the clipboard itself and stays silent, since a paste carries other things (text) as a matter of course.
- **`lib/pictureExport.ts`** — `savePictureAs(dataUrl, format, name)`: the save dialog in the vault's `export/` folder (`exportDefaultPath` in `lib/vaultManager.ts`, every export's starting place) under `exportFilename`'s name (`lib/helpers.ts`, `<name>_<yyyy-MM-dd>.<ext>`, every export's default), then `export_image`; what a place's canvas export dialog ends in. `textDataUrl` turns an SVG's text into the data URL `export_image` decodes.
- **`lib/imageLimits.ts`** — applies the vault's image settings to an inserted image: `prepareImageDataUrl(dataUrl, { capBytes? })` scales to the max edge (GIF/SVG excepted — scaling would lose the animation or the vectors), then checks the max file size (and an optional caller cap; the smaller wins), throwing `ImageTooLargeError`; `hasImageLimits()`; `readIconFile`; `imageSizeLabel` (a rounded "N MB", deliberately not `formatBytes`, which would drop to KB at exactly the sizes these settings offer).
- **`lib/emojiSearch.ts`** — `DEFAULT_EMOJI_PICKER_EMOJIS`, the per-locale search data (`emojiSearchLocale`/`cachedEmojiSearchData`/`loadEmojiSearchData`, lazy `import()`, module-level cache), `searchEmojis(data, query)`. Separate from `EmojiPicker.tsx` so `useEmojiSearchData` can load it without importing the component.
- **`lib/altarBackground.ts`** — `altarBackgroundUrl(src)` tells the app's own background pictures (`public/backgrounds`) from a vault's image and turns either into a URL to show, through `imageSrc()` for anything not the app's own (see [Altars as entries](architecture/editors.md#altars-as-entries)).

The Zustand stores and the hooks are the shared state and behaviour layer. Holding data in a component that two views need means the wrong place was chosen.

## When Deviating Is Right

Three cases that have been examined and settled. They are not sloppiness and should not be "tidied up".

**`.picker-tile` instead of `.panel-interactive`.** The vault picker's tiles (and the start page's theme cards, `.start-theme`) look like `.panel-interactive` and take its tokens, but are classes of their own, because `.panel` does not take an active tint: theme overrides beat modifier classes, and unlayered rules come later in the output than `@layer components`. Both traps are described in [`design.md`](design.md#specificity-traps) — they hit **every** new "active" variant on an existing `.panel` card, not just the vault picker.

**`MenuDropdown` alongside `ContextMenu`.** Two dropdown implementations, on purpose. `ContextMenu` positions itself at a cursor coordinate, has a timing trick to survive the right-click that opened it, and knows disabled entries but no submenus. The title bar's menu buttons need submenus too.

**The `EmojiPicker`'s trigger stays free.** A large image/emoji button with a label in an icon field and a bare emoji glyph in a category row have nothing in common but their function. What is unified is the popover, not the trigger.

What is **not** a valid deviation: "it was faster this way", "just this one place", "looks almost the same". What the three cases above have in common is that the shared variant *would not have worked technically* or is *structurally something else*.

## Known Duplication

Open, deliberately recorded, and not an excuse for further copies.

1. **Two surface class sets for dropdowns.** `.menu-surface`/`.menu-item`/`.menu-separator` for the title bar's menus, `.context-menu*` for the context menu. Colours run on the same tokens and the row height matches; the structural classes are still doubled, and `Dropdown`'s rows repeat them a third time, as does the text editor's `[[` list (`SuggestionList`, with its jade current row); its `/` list (`CommandList`) runs on `.menu-surface`/`.menu-item` with `.menu-item--current`. Resolving this means reducing `ContextMenu` to `.menu-surface`/`.menu-item` plus its `danger` variant, and moving `SuggestionList` onto them too.
2. **`LinkPickerModal` is hand-built on the inside.** Only the outer shell runs through `Modal`; its three icon-only tabs (all, entries, tasks) are a hand-written toggle rather than `TabIconButton`, whose active state is the stone tone while the picker needs jade (see [design.md Open Points](design.md#open-points)).
3. **A third dropdown row class**, `linked-entry-menu-item` (`LinkedEntryPicker`), with its own raw chain rather than `.menu-item`/`.context-menu-item-*`.
4. **Eight separate "emoji or icon file" glyph renderers.** `ItemGlyph` (dashboards), `BlockGlyph`, `FaviconGlyph`, `LinkItemIcon` (`LinkedEntryPicker`, also used by `LinkPickerModal`), `TabBar`'s private `renderIconValue`, the `getIcon` of `LeftSidebarEntryList`, `InternalLinkNodeView` and `MediaPreview` (`EditProperties`) each branch on `isImageIcon` and write their own `<img src={iconSrc(…)}>` — different sizes, rounding, border and `object-contain` vs. `-cover`. A change of how an icon becomes a source touches all of them. *Cost: one `IconGlyph` parameterised on size and an appended class, the others delegating to it.*

Whoever touches one of these places anyway clears it up along the way. New entries in this list need a reason why resolving it was not possible right away.
